# نصب کند `alpha.55` — چه چیزی اندازه گرفته شد و چه چیزی لازم است

جواب بند ۱۰ دستور. دستور صریح است: **بدون شواهد، کش، میزبان، Wordfence یا
بسته را علت قطعی نام نبر.** این سند هیچ علتی اعلام نمی‌کند. سه چیز می‌گوید:
چه چیزی در این محیط اندازه‌گیری شد، چه چیزی از این اندازه‌گیری‌ها **نتیجه
نمی‌شود**، و دقیقاً کدام لاگ لازم است.

## ۱. آنچه اندازه‌گیری شد

### ۱٫۱ بسته

| چه چیزی | اندازه |
|---|---|
| حجم ZIP | ۱٬۵۷۷٬۸۵۸ بایت (۱٫۵ مگابایت) |
| تعداد فایل | ۵۵۹ |
| حجم باز‌شده | ۴٬۴۱۴٬۴۶۳ بایت (۴٫۴ مگابایت) |
| بزرگ‌ترین فایل | `assets/fonts/vazirmatn-variable.woff2` — ۱۱۱ کیلوبایت |
| زمان باز‌کردن روی این ماشین | **۰٫۰۷ ثانیه** |
| یک دایرکتوری در سطح اول ZIP | بله (گاردِ packaging) |

و روند رشد، برای اینکه «بسته بزرگ شده» حدس نماند:

| بسته | فایل | بایت |
|---|---|---|
| `alpha.53` | ۵۵۰ | ۱٬۴۷۲٬۵۱۰ |
| `alpha.54` | ۵۵۱ | ۱٬۴۸۶٬۶۸۳ |
| `alpha.55` | ۵۵۶ | ۱٬۵۳۲٬۳۰۶ |
| `alpha.56` | ۵۵۹ | ۱٬۵۷۷٬۸۵۸ |

**چهار درصد رشد از `alpha.53` به `alpha.55`.** اگر `alpha.53` با تأخیر نصب
نشده و `alpha.55` شده، حجم بسته این را توضیح نمی‌دهد.

### ۱٫۲ هیچ تماس شبکه‌ای در افزونه نیست

`grep` روی کل `src/` و دو فایل ریشه، برای `wp_remote_*`، `curl_init`،
`fsockopen`، `stream_socket_client`، `WP_Http` و
`file_get_contents('http…')`: **صفر مورد**. افزونه در هیچ مسیری — فعال‌سازی،
ارتقا، یا هر درخواست دیگر — بیرون از سایت تماس نمی‌گیرد. اندازه‌گیری فعال‌سازی
پایین هم `http_calls_during_activation=0` می‌دهد.

این یعنی **انتظار برای یک سرور بیرونی، اگر هست، مال این افزونه نیست**. چه
چیزی هست را این سند نمی‌گوید؛ نمی‌داند.

### ۱٫۳ پنج گامِ فعال‌سازی، تک‌تک زمان‌گرفته

روی وردپرس یکبارمصرف (۳۲ محصول ووکامرس، ۳ افزونهٔ فعال، ساختار داده از قبل
روی ۲۸):

| گام | میلی‌ثانیه | statement |
|---|---|---|
| نصب مجوزها (`CapabilityInstaller`) | ۰٫۲۲ | ۰ |
| تنظیمات (`ensureStored`) | ۰٫۰۵ | ۰ |
| زنجیرهٔ migration روی ساختار هدف | ۰٫۸ | ۱ |
| جابه‌جایی مدارک قدیمی | ۰٫۴۳ | ۰ |
| `addRewriteRules()` + `flush_rewrite_rules(false)` | ۰٫۸۷ | ۰ |

**جمع زیر ۳ میلی‌ثانیه.** `rewrite_rules` روی این سایت ۱۸۹ قاعده و ۱۸ کیلوبایت
است و چون قاعده‌ها عوض نمی‌شوند، هیچ نوشتنی هم ندارد.

شاهد: `docs/evidence/alpha56-reproduction/after-install-timing.txt`،
با `wp eval-file tests/Support/alpha56-probe.php install-timing`.

### ۱٫۴ کدام گام migration با اندازهٔ سایت بزرگ می‌شود

از ۲۸ گام زنجیره، **چهار** گام روی ردیف‌های موجود می‌نویسند و بقیه فقط
`CREATE TABLE IF NOT EXISTS` یا `ALTER TABLE` اند:

| گام | چه می‌نویسد | روی کدام جدول |
|---|---|---|
| `M0006CatalogAndOrders` | `wc_product_id = 0` را `NULL` می‌کند | `tmc_products` |
| `M0019BaselineAndDecisions` | ردیف تصمیم برای محصول‌های موجود | `tmc_product_decisions` |
| `M0020ProductTitleSort` | کلید مرتب‌سازی، **دسته‌ای ۲۰۰ ردیفی** | `tmc_products` |
| `M0028MinMaxHandoverLiveKey` | `live_key = post_id` | `tmc_minmax_handover` |

**هیچ‌کدام روی `wp_posts` یا `wp_postmeta` نمی‌نویسند.** یعنی هزینهٔ این چهار
گام با تعداد ردیف‌های **خودِ بازارگاه** بزرگ می‌شود، نه با کاتالوگ سایت — و
روی سایت مالک آن تعداد کوچک است (۱۲ محصول با قاعدهٔ Min Max، و دفتر انتقال
خالی چون هیچ migration ای اجرا نشده). و `M0020` از همان اول دسته‌ای است، پس
حتی روی کاتالوگ بزرگ هم در یک درخواست تمام نمی‌شود و لازم هم نیست.

## ۲. آنچه از این اعداد نتیجه **نمی‌شود**

- **این «فعال‌سازی سریع است» نیست.** پنج گام بالا روی سایتی اجرا شدند که
  ساختار داده‌اش از قبل روی ۲۸ بود. اولین نصب، زنجیرهٔ ۲۸ گامی را **از صفر**
  می‌دواند و آن یک عدد دیگر است که این محیط نمی‌تواند نمایندهٔ سایت مالک
  باشدش: `information_schema` روی یک میزبان اشتراکی با هزاران جدول، و
  `ALTER TABLE` روی `wp_postmeta` ِ یک سایت واقعی، هیچ‌کدام شبیه اینجا نیست.
- **«Stalled» در مرورگر دربارهٔ PHP حرف نمی‌زند.** در Chrome، `Stalled` مدت
  **پیش از فرستادن** درخواست است: صف اتصال، proxy، یا DNS. زمان اجرای سرور
  `Waiting (TTFB)` است و جای دیگری در همان پنل. این یک واقعیت دربارهٔ ابزار
  است، نه ادعایی دربارهٔ سایت مالک — و دقیقاً به این دلیل، **تا وقتی معلوم
  نشود کدام‌یک از آن دو بزرگ بود، علت قابل نام‌بردن نیست**.
- **هیچ‌کدام از کش، میزبان، Wordfence و بسته علت اعلام نمی‌شوند.** چیزی دربارهٔ
  هیچ‌کدامشان اندازه‌گیری نشده.

## ۳. درخواست کوتاه و دقیق — چه چیزی لازم است

برای اینکه این بسته شود، سه چیز لازم است و هیچ‌کدام دسترسی به سایت نمی‌خواهد:

1. **از پنل Network مرورگر، در همان لحظهٔ نصب:** برای درخواستِ
   `update.php?action=upload-plugin` (یا `plugin-install.php`)، چهار عدد از
   زبانهٔ **Timing**: `Stalled`، `Request sent`، `Waiting (TTFB)` و
   `Content Download`. یک اسکرین‌شات از همان زبانه کافی است.
   *چرا:* این چهار عدد، «شبکه» را از «سرور» جدا می‌کنند. بی آن‌ها هر جواب
   دیگری حدس است.
2. **لاگ خطای PHP میزبان**، تنها برای **بازهٔ ۱۰ دقیقه‌ای** حولِ همان نصب
   (ساعت دقیق نصب را بگویید). دنبال سه چیزیم: `Maximum execution time`،
   `Allowed memory size`، و هر `mysqli`/`wpdb` timeout.
   *چرا:* اگر فعال‌سازی وسط راه کشته شده باشد، دروازهٔ ارتقا دفعهٔ بعد ادامه
   می‌دهد و ظاهرش «کند بود ولی شد» است — که با «سریع بود» از بیرون فرق
   ندارد.
3. **یک عدد از همان سایت، پس از نصب:** صفحهٔ «سلامت» → ساختار دادهٔ فعلی، و
   اگر خطایی ثبت شده، متنش.
   *چرا:* اگر ساختار داده روی عددی پایین‌تر از هدف مانده باشد، نصب **تمام
   نشده** و کندی علامتِ آن است نه خودِ مسئله.

**آنچه لازم نیست:** دسترسی SSH، cPanel، کلمهٔ عبور، یا خروجی کامل دیتابیس.
هیچ‌کدام از سه مورد بالا چنین چیزی نمی‌خواهد.

## ۴. و یک چیز که همین حالا می‌شود کرد

اگر نصب دوباره کند بود، **پیش از هر کار دیگری** صفحهٔ سلامت را باز کنید و
ساختار دادهٔ فعلی را بخوانید. دو جواب، دو مسیر کاملاً متفاوت:

- **روی ۲۸ است** ⇒ نصب تمام شده و مسئله سرعتِ یک درخواست بود، نه درستی. مورد
  ۱ بالا (چهار عدد Timing) کافی است.
- **زیر ۲۸ است** ⇒ زنجیره وسط راه ایستاده. دروازهٔ ارتقا خودش تلاش دوباره
  می‌کند ولی با فاصلهٔ **۳۰۰ ثانیه** (`UpgradeGate::RETRY_COOLDOWN_SECONDS`)،
  و تا آن وقت صفحهٔ سلامت دلیلش را نشان می‌دهد. آن دلیل را بفرستید؛ آن وقت
  علت معلوم است و حدس لازم نیست.
