## ۱) سوییت‌ها، روی **هر دو** مفسر

| سوییت | PHP 8.3.6 | PHP **8.1.34 واقعی** (کانتینر) |
|---|---|---|
| unit | **PASS** — ۹۱۴ آزمون، ۶۰۶٬۳۰۲ assertion | **PASS** — همان اعداد |
| architecture | **PASS** — ۳۵۳ آزمون، ۷٬۰۷۲ assertion | **PASS** — همان اعداد |
| contract | **PASS** — ۴۱۳ آزمون، ۲٬۵۸۶ assertion | **PASS** — ۴۱۳ آزمون، ۲ skip با نام |
| database | **PASS** — ۱۲۶۵ آزمون، ۱۴٬۴۹۴ assertion | **PASS** — ۱۲۶۵ آزمون، ۱۴٬۴۹۴ assertion — **صفر تفاوت به ازای هر آزمون** |
| packaging | **PASS** — ۳۲ آزمون، ۵۲٬۱۶۸ assertion | ⛔ **`Not Run`** — ایمیج `git`/`zip`/`unzip` ندارد |

⛔ **و یک عددِ تکرارنشده، گزارش‌شده نه توضیح‌داده‌شده:** اولین اجرای database
روی ۸٫۳٫۶ در این دور **۱۴٬۴۹۸** داد و دو اجرای بعدی — یکی روی هر مفسر —
هر دو **۱۴٬۴۹۴**، با **صفر تفاوت به ازای هر آزمون** (دو لاگ JUnit، مقایسه‌شده
آزمون‌به‌آزمون). پس مفسر متغیرِ آن چهار assertion **نیست**. آن اجرای اول لاگ
به‌ازای‌آزمون ندارد، پس آزمونش نام برده نمی‌شود و حدس هم زده نمی‌شود؛ آنچه
ثبت می‌شود این است: چهار assertion در اجرایی که بلافاصله پس از حلقهٔ
falsification افتاد، و `setUp()` مشترکِ این سوییت جدول‌های خودِ افزونه را
truncate نمی‌کند (هر کلاس فیکسچر خودش را دارد). **عددی که در این سند
می‌مانَد ۱۴٬۴۹۴ است**، چون دو اندازه‌گیریِ مستقل روی آن توافق دارند.

⛔ **و سوییت database هر بار تنها دوانده شد** (`alpha.40`/`alpha.98`)، با این
شرط پیش از هر اجرا:

```bash
pgrep -af phpunit
php -r '…SELECT COUNT(*) FROM information_schema.PROCESSLIST WHERE DB="tmc_test"…'
php -r '…SHOW TABLES LIKE "%_away"…'
```

⛔ **دو skip روی ۸٫۱٫۳۴ عمدی و نام‌دار اند:** ایمیج `intl` ندارد، پس
`tmc_stub_remove_accents()` جوابِ دیگری می‌دهد و `SanitizeTitleTest` **فقط
همان یک ردیف** را skip می‌کند؛ پانزده جفتِ فارسیِ pin‌شده روی **هر دو** مفسر
اندازه‌گیری می‌شوند، و خودِ predicate در **هر دو جهت** assert می‌شود تا یک
skip ِ پهن‌تر، سوییت را دوباره `OK` نگوید.

⛔ **و سوییت packaging روی ۸٫۱٫۳۴ `Not Run` است با علتِ نام‌برده، نه «قبول»:**
آن سوییت به `git`، `zip` و `unzip` شل می‌زند، ایمیج هیچ‌کدام را ندارد و
آرشیوهای دبیان از این محیط در دسترس نیستند. آن سوییت **بیلد** را می‌سنجد نه
مفسر را، و روی میزبان اندازه‌گیری شد.

## ۳) falsification — ۱۴ جهش

هر جهش یکی از اصلاح‌های همین دور است که **غلط برگردانده شده**، روی درختِ
آرام، با بازگرداندن **بایت‌به‌بایت** و مقایسهٔ هش.

| # | چه چیزی را می‌شکند | سوییت | نتیجه |
|---|---|---|---|
| ۱ | پنل از ووکامرس دربارهٔ والدِ واردشده نمی‌پرسد | database | falsified |
| ۲ | فهرست دامنهٔ قیمت واقعی را نمی‌پرسد | database | falsified |
| ۳ | چهار فعل ویرایش، تنوع‌های فروشگاه را رد نمی‌کنند | database | falsified |
| ۴ | فعل موجودی به‌تنهایی (درِ پنجم) | database | falsified |
| ۵ | سمت فروشگاهِ خوانده‌نشده «پیوندخورده» گزارش می‌شود | unit + database | falsified |
| ۶ | صفحهٔ کوتاه به‌عنوان صفحهٔ کامل گزارش می‌شود | database | ⛔ **پاس اول: جان سالم برد** · پاس دوم: falsified |
| ۷ | گزارش همان ردیف‌هایی را که برایشان ساخته شده می‌اندازد | database | falsified |
| ۸ | جهت دیگر `post_author` را می‌خواند | architecture + database | falsified |
| ۹ | هر فروشگاهی که نمی‌فروشد «تمام‌شده» خوانده می‌شود | database | falsified |
| ۱۰ | آرشیوِ خوانده‌نشده هم مهاجرت را تمام می‌کند | database | falsified |
| ۱۱ | دروازهٔ دومِ باز پشت جوابِ «فقط سوابق» پنهان می‌شود | unit + database | falsified |
| ۱۲ | شناسهٔ داخلی به‌جای جمله روی صفحهٔ مدیر | database | falsified |
| ۱۳ | `post_author` روی محصولی که از قبل بود بازنویسی می‌شود | contract | falsified |
| ۱۴ | منو به ترتیب ثبت چاپ می‌شود نه به ترتیب تعریف‌شده | contract | falsified |

**۱۴ از ۱۴ falsify شد، سیزده در پاس اول و یکی در پاس دوم.**

⛔ **و جهش ۶ که جان سالم برد، حفرهٔ آزمونِ خودم بود نه نقص کد.** هر آزمونِ
`CatalogueReconciliationTest` دیتابیسِ **سالم** می‌خواند، جایی که شمارش و
فهرست همیشه می‌خوانند — پس گاردِ «صفحهٔ کوتاه `null` است» **قابل‌رسیدن نبود**،
و گاردِ قابل‌رسیدن‌نبوده از گاردِ غایب قابل تشخیص نیست (`alpha.80`). بسته شد
با آزمونی که شکست را **با نام** داخل statement ِ فهرست تزریق می‌کند و
`COUNT(*)` کنارش را سالم می‌گذارد، به‌علاوهٔ **کنترلِ مخالف**: با قطع تزریق،
همان فراخوان کلِ صفحه را جواب می‌دهد.

⛔ **و خطِ مبنای پایانیِ حلقه `database-all: 7` داد، و آن عدد دربارهٔ هیچ
درختی نیست:** هم‌زمان با آن یک runner دومِ database روی همان دیتابیس زدم
(`alpha.40`، بار چهارم). جزئیاتش در خودِ
`docs/evidence/alpha105-falsification/falsification.txt` نوشته شده، و اعداد
تمیزِ این سند از اجرای **تنها** روی درختِ آرام می‌آیند.
