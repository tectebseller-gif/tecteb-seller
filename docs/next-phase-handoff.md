## ۴. آنچه فاز ۲ می‌تواند مستقیم روی آن بنا کند

| قابلیت آماده | محل | نکته برای مصرف‌کننده بعدی |
|---|---|---|
| بارگذار ماژول با مهار خرابی | `Core/Modules/` | ماژول جدید فقط manifest و دو متد لازم دارد؛ وابستگی خراب خودکار مسدود می‌کند |
| migration مرحله‌ای + قفل مالک‌دار | `Core/Migration/` | مرحله جدید باید ایدمپوتنت باشد و `verify()` واقعی داشته باشد؛ `SchemaVersion::TARGET` را یک واحد بالا ببرید |
| تنظیمات با اعتبارسنجی و audit | `Core/Config/`, `Modules/Admin/` | کلید جدید را در `SettingsSchema` و `Settings` اضافه کنید؛ الگوی «کلید فرم ≠ کلید ذخیره‌شده» را برای هر مقدار مقیاس‌دار تکرار کنید |
| لاگ ممیزی | `Core/Audit/` | رویداد جدید **باید** در `AuditEventCatalog` allowlist شود، وگرنه ثبت نمی‌شود |
| قرارداد OTP | `Contracts/Otp/` | تنها پیاده‌سازی ارسالی NullProvider است؛ Adapter دروازه فقط با مستند API عمومی |
| قفل خروجی | `Core/Environment/OutboundPolicy.php` | هر sender آینده **باید** اول `assertAllowed()` را صدا بزند؛ الان همیشه استثنا می‌دهد |
| اجزای رابط فارسی/RTL | `Modules/Admin/Presentation/` | Button/Field/ErrorSummary/StatusBadge/DataList/Notice موجودند و کنتراستشان محاسبه شده |
| زیرساخت آزمون | `tests/`, `tools/` | چهار سطح شاهد جدا؛ لطفاً مخلوطشان نکنید |

## ۵. قواعدی که فاز ۲ نباید نقض کند

1. `Core`, `Contracts` و `Application` هیچ‌وقت WordPress صدا نمی‌زنند —
   `tests/Architecture` این را می‌گیرد.
2. هیچ رویداد audit خارج از allowlist؛ هیچ raw request در لاگ.
3. `null` هرگز به `false` تبدیل نمی‌شود؛ «نامشخص» یک وضعیت واقعی است.
4. هیچ ماژول `planned` دکمه فعال‌سازی نمی‌گیرد.
5. خروجی TMC تا تصمیم صریح مالک بسته می‌ماند.
6. `Not Run` هرگز بدون log قابل بازتولید به `Passed` تبدیل نمی‌شود.
7. تصاویر خارج از WordPress «نمونه رابط»اند، نه اثبات کارکرد.
8. اعتبارسنجی، ذخیره و ممیزی سه رویداد جدا هستند: هیچ ردیف ممیزی پیش از
   تأیید ذخیره نوشته نمی‌شود و هیچ پیام موفقیتی برای نوشتن انجام‌نشده.
9. اجرای منسوخ‌شده migration حق تغییر نسخه یا وضعیت اجرای جدید را ندارد؛ هر
   مرحله جدید باید ایدمپوتنت باشد وگرنه به ADR جدا نیاز دارد (ADR-003 §۳٫۱).
10. `stored > target` هرگز مهاجرت نمی‌شود و هرگز Healthy اعلام نمی‌شود.

## ۶. اگر محیط ساخت باز شود

با دسترسی به `downloads.wordpress.org` و PPA پی‌اچ‌پی، این‌ها بلافاصله
اجراشدنی می‌شوند و باید پیش از فاز ۲ اجرا شوند:

1. suite integration واقعی WordPress (جایگزین سطح stub، نه حذف آن — ADR-005).
2. ماتریس HPOS در چهار حالت.
3. `php -l` و اجرای کامل آزمون‌ها روی PHP 8.1.34.
4. بررسی رابط روی wp-admin واقعی در پنج عرض و zoom ۲۰۰٪.
