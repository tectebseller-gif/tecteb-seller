# دسترس‌پذیری و چیدمان روی wp-admin واقعی

اجرای `tools/browser/check-wpadmin.mjs` روی همان WordPress یکبارمصرف پذیرش،
با نشست واقعی مدیرکل. این با `docs/evidence/browser-checks.json` فرق دارد:
آن یکی harness را **بیرون از WordPress** می‌سنجد و «نمونه رابط» است؛ این یکی
صفحه‌ها را همان‌طور می‌سنجد که وردپرس واقعاً سرو می‌کند — با نوار مدیریت،
منوی مدیریت، CSS هسته و markup خود افزونه داخل همه آن‌ها.

| پوشه | WooCommerce | نتیجه |
|---|---|---|
| `wpadmin-a11y/` (همین‌جا) | **غیرفعال** | ۱۸۸ بررسی، ۰ شکست |
| `../wpadmin-a11y-with-wc/` | **فعال (11.0.1)** | ۱۸۸ بررسی، ۰ شکست |

## چه چیزی سنجیده شد

چهار صفحه (`tmc-dashboard`، `tmc-health`، `tmc-settings`، `tmc-modules`) در
پنج viewport ۳۲۰/۳۷۵/۷۶۸/۱۰۲۴/۱۴۴۰ و زوم ۲۰۰٪ (۱۲۸۰×۱۰۲۴ در مقیاس ۲ ≈
۶۴۰×۵۱۲ پیکسل CSS):

| بررسی | چه چیزی را رد می‌کند |
|---|---|
| `no-horizontal-page-scroll` | اسکرول افقی کل سند؛ اگر رخ دهد، عنصر مقصر نام‌گذاری و «افزونه» یا «هسته» علامت می‌خورد |
| `no-element-overflow` | بیرون‌زدن هر عنصر **افزونه** از viewport |
| `touch-target-44px` | هدف لمسی کوچک‌تر از ۴۴×۴۴ (لینک‌های داخل متن مستثنا) |
| `no-js-errors` | خطای JavaScript در صفحه |
| `plugin-assets-load` | شکست بارگذاری asset خود افزونه |
| `axe-wcag-aa-plugin` | axe-core روی `.tmc-admin` با تگ‌های wcag2a/2aa/21a/21aa/22aa |
| `axe-whole-page-recorded` | axe روی **کل** سند؛ یافته‌های بیرون از `.tmc-admin` جدا ثبت می‌شوند |
| کیبورد | لینک پرش اولین توقف افزونه است، همه توقف‌ها حلقه focus دارند، پرش واقعاً به `#tmc-main` می‌رسد |
| صفحه خطا | ارسال مقدار نامعتبر: خلاصه خطا وجود دارد، هنگام بارگذاری focus می‌گیرد، و لینک‌هایش قابل دسترسی‌اند |

## نتیجه

در هر دو اجرا، **صفر** یافته axe — نه داخل markup افزونه و نه بیرون از آن
(`foreign_findings: []`). هیچ اسکرول افقی در هیچ viewport و در زوم ۲۰۰٪.
هیچ خطای JavaScript. همه asset‌های افزونه بارگذاری شدند.

تنها میزبان خارجی که sandbox رد کرد `secure.gravatar.com` است — آواتار نوار
مدیریت خود وردپرس، نه درخواست افزونه؛ در `blocked_external_hosts` ثبت شده است.

## فایل‌ها

| فایل | چیست |
|---|---|
| `wpadmin-a11y.json` | نتیجه تک‌تک ۱۸۸ بررسی + نسخه ابزارها |
| `wpadmin-a11y.log` | خلاصه خوانا |
| `screenshots/*-375.png`، `*-1440.png` | تصویر تمام‌صفحه هر صفحه در دو عرض |
| `screenshots/*-zoom200.png` | همان صفحه در زوم ۲۰۰٪ |
| `screenshots/settings-error-1024.png` | صفحه تنظیمات در حالت خطای اعتبارسنجی |

**این تصاویر «نمونه رابط» نیستند.** از خود wp-admin با نشست معتبر گرفته شده‌اند
و نوار مدیریت وردپرس در بالای آن‌ها دیده می‌شود. تصاویر
`docs/evidence/screenshots/` همچنان نمونه رابط harness هستند.

## آنچه این اجرا ثابت نمی‌کند

بررسی خودکار جای **screen reader دستی** را نمی‌گیرد؛ آن سطر همچنان `Not Run`
است. اجرا روی Chromium بود؛ Firefox و Safari آزموده نشده‌اند. قالب فعال سایت
مالک و افزونه‌های آن (LiteSpeed، Hello Elementor، Persian Woo، …) حاضر نبودند.
