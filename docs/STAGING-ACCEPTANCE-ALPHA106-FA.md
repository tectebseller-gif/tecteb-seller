# `alpha.106` — سه گام staging، و هر سه فقط‌خواندنی

**این سند تنها دستورالعمل اجرایی این دور است.** سه گام، هیچ‌کدام چیزی
نمی‌نویسد، و هیچ‌کدام دکمهٔ ذخیره را فشار نمی‌دهد.

⛔ **و بیست‌ونه ردیف `docs/STAGING-ACCEPTANCE-NEXT-FA.md` همچنان `Not Run`
اند و این سند جایشان را نمی‌گیرد.** آن‌ها پیش‌شرط انتشار تولیدند؛ این سه گام
فقط می‌گویند آیا اصلاح‌های همین بسته روی دادهٔ واقعی همان کاری را می‌کنند که
روی فیکسچر کردند.

⛔ **پیش از هر گام: پشتیبان کامل دیتابیس و فایل.** این بسته هیچ migration ای
ندارد و بازگشتش فقط تعویض ZIP است (بند ۸۶)، ولی گام ۳ عددی می‌دهد که ممکن است
بعدش کسی بخواهد رویش اقدام کند — و آن اقدام **در این سه گام نیست**.

**قبول یعنی هر پنج:**

## گام ۳ — یک گزارش اختلاف، فقط‌خواندنی

**کار:** یک بار این را بدوانید و فایلش را نگه دارید:

```bash
wp eval-file tools/production-audit.php products --csv > tmc-products.csv
```

⛔ **این ابزار هیچ فعل نوشتنی ندارد** و `ReadOnlyInventoryTest` همین را از
بایت‌های خودش می‌سنجد. هیچ سفارشی، قیمتی، موجودی‌ای یا دسته‌ای را عوض
نمی‌کند.

**چه چیزی را بخوانید:** هر ردیفی که ستون `wcType` اش `variable` است. برای
آن‌ها:

| ستون | معنای سالم | معنای «روی والد نوشته شده» |
|---|---|---|
| `stockQty` | **خالی** (ووکامرس عدد را روی فرزندان نگه می‌دارد) | عددی مثل `0` |
| `purchasable` | `yes` | `no` |
| `minPrice` / `maxPrice` | دامنهٔ تنوع‌ها | خالی، در حالی که `variations` پر است |

**جوابی که این گام می‌دهد:** چند والدِ متنوع **از قبل** `_stock` نوشته‌شده
دارند. از این بسته به بعد هیچ والد تازه‌ای به آن فهرست اضافه نمی‌شود.

⛔ **و تصحیحِ آن ردیف‌ها در این سه گام نیست.** این بسته عمداً برنمی‌گرداندشان،
چون بازگرداندنِ خودکار یعنی حدس‌زدن اینکه پیش از نوشتن چه بوده. اگر فهرست
ناخالی بود، **تصمیمِ مالک** است که با چه عددی و روی کدام محصول تصحیح شود — و
آن یک دستور جداگانه می‌خواهد.
