# ثبت تصمیم‌های معماری (ADR)

هر ADR یک تصمیم فنی، زمینه، گزینه‌های بررسی‌شده، دلیل انتخاب، پیامدها و شرط
بازنگری را ثبت می‌کند. ADRها قاعده تجاری نمی‌سازند؛ مرجع قواعد تجاری سند
مادر و `docs/decision-log.md` است.

| شناسه | عنوان | وضعیت |
|---|---|---|
| [ADR-001](ADR-001-autoloader.md) | autoloader اختصاصی PSR-4 محدود به namespace افزونه، به‌جای autoloader زمان اجرای Composer | **پذیرفته‌شده** (پیش از پیاده‌سازی؛ آزمون‌های آن در فاز ۱ اجرا می‌شوند) |
| [ADR-002](ADR-002-two-phase-module-loading.md) | بارگذاری دومرحله‌ای ماژول (register → boot) و مهار خرابی با وضعیت‌های degraded/blocked | **پذیرفته‌شده** |
| [ADR-003](ADR-003-schema-versioning-and-migration.md) | نسخه schema مستقل از نسخه انتشار، migration مرحله‌ای و قابل resume، قفل مالک‌دار | **پذیرفته‌شده** |
| [ADR-004](ADR-004-settings-storage.md) | یک option آرایه‌ای schema-versioned؛ کلید فرم جدا از کلید ذخیره‌شده | **پذیرفته‌شده** |
| [ADR-005](ADR-005-wordpress-stub-layer.md) | لایه stub وردپرس در آزمون و مرزی که ادعا نمی‌کند | **پذیرفته‌شده** |

قالب: `ADR-NNN-slug.md` با بخش‌های زمینه، گزینه‌ها، تصمیم، محدوده، آزمون،
پیامدها، شرط بازنگری.
