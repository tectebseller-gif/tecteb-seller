# ماتریس پذیرش `0.1.0-alpha.109` — §۱۳

این سند سه چیز را **جدا** نگه می‌دارد، چون §۱۳ صریحاً خواسته بود:
آزمونی که روی **بدل** می‌دود · آزمونی که روی **وردپرس و ووکامرس واقعی**
می‌دود · و چیزی که **اجرا نشده**. هیچ‌کدام به‌جای دیگری گزارش نمی‌شود، و
`NOT RUN` نه PASS است و نه FAIL.

⛔ **و هر نقصِ این دور یک آزمون بازتولید دارد، با نام.** جدول «ب» هر نقص را
به آزمونی وصل می‌کند که روی کدِ **پیش از اصلاح** شکست می‌خورد. جایی که چنین
آزمونی وجود ندارد، در جدول «ت» با دلیل گفته می‌شود.

## پ) آنچه روی وردپرس و ووکامرس **واقعی** اندازه‌گیری شد

شواهد خام: `docs/evidence/alpha109-live/generate-and-price.txt`.
محیط: وردپرس ۷٫۱ یکبارمصرف، ووکامرس ۱۱٫۰٫۱، دیتابیس `tmc_demo`، محصول ۱۵.
هر نوشتن از **POST خودِ فرم فروشنده** رفت، نه از یک `wp eval` به سرویس.

| § | ادعا | اندازه‌گیری |
|---|---|---|
| ۳ | ویژگی می‌تواند مشخصه باشد | `wcattr_جنس_variation=no` · `wc_variation_attribute_count` ۲ → **۱** |
| ۳ | و محصول از ویرایش خارج نمی‌شود | `resave_code=variation_saved` · قیمت ۱۲۵٬۰۰۰ → ۱۳۰٬۰۰۰ اعمال شد |
| ۴ | ساخت گروهی، بی تکرار | ردیف‌ها ۳ → **۹** · «۶ تازه، ۳ دست‌نخورده» · تکرار دکمه: **صفر** |
| ۴ | و ممیزی ثبتش می‌کند | `product.saved status=variations_built` سپس `product.synced` |
| ۷ | ردیفِ بی‌قیمت فرزند نمی‌شود | فرزندان **۳** برای ۹ ردیف · دامنه **۱۳۵٬۰۰۰ – ۴۰۰٬۰۰۰** |
| ۵ | کارتِ هر ترکیب می‌نویسد | ردیف ۱۳ → `145000 / PK50-PLA / 5` · فرزند تازه **۲۶** با همان سه مقدار |
| ۷ | و بی تکرار | **۴** فرزند برای **۴** ردیفِ قیمت‌دار، هر یک با مهر یکتا |
| ۹ | صفحهٔ عمومی | `variations_form` · دو انتخاب‌گر محور · جدول مشخصات · ۴ تنوع در JSON |
| ۱۰ | سبد | «۵۰ عددی · پلاستیک · ۱۴۵٬۰۰۰ × ۲ = ۲۹۰٬۰۰۰» |
| ۱۰ | سفارش، **بی پرداخت واقعی** | سفارش‌های **۲۷** و **۲۸**، `cod`، `date_paid=false` |
| ۱۰ | قلم و موجودی | `variation_id=26 qty=2` · موجودی **همان فرزند** ۵ → ۳ |

| ۱۰ | دفترکل | `vendor_earning −2900000000 / central_payment +2900000000` — **متوازن** |
| ۱۲ | شناسهٔ تکراری | **صفر** روی ۳۴ فرم · ۳۴ nonce و ۳۴ referer |

⛔ **و یک تصحیحِ اندازه‌گیریِ من، چون مهم‌تر از نتیجه است:** اول «بازارگاه
هیچ قلمی ثبت نکرد» گزارش شد. **کوئریِ من غلط بود**، نه افزونه: ستونی به نام
`wc_variation_id` نوشته بودم که وجود ندارد (`variation_id` هست)، و

⛔ **و کلید آزمایشی سفارش لازم نبود:** برای سفارش دوم روشن و بعد **خاموش** شد،
و سفارش ۲۷ **پیش از** لمس‌شدنش ثبت شده بود. پس بخشی از این اثبات نیست.
