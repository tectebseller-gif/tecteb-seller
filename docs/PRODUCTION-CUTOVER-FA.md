## ۱. ترتیب، و چرا یک‌طرفه است

```
الف) پشتیبانِ آزموده‌شده
      ↓
الف-۲) توقف کنترل‌شدهٔ فروش  ← ⛔ با مکانیزم خودش، نه با غیرفعال‌سازی
      ↓
ب) نصب alpha.103 روی تولید  ← هیچ‌چیز جابه‌جا نمی‌شود
      ↓
پ) پیش‌پرواز (فقط خواندن)  ← دکان هنوز روشن
      ↓
ت) تطبیق مالی و تأییدِ سوابق هر فروشگاه  ← ⛔ فقط تا وقتی دکان روشن است
      ↓
ث) انتقال مالکیت، دسته‌دسته  ← دکان هنوز روشن، فروش هنوز بسته
      ↓
ث-۲) تصمیم پوشش کمیسیون  ← ⛔ پیش از بازکردن فروش
      ↓
ث-۳) ثبت پایهٔ نشانی فروشگاه دکان  ← ⛔ پیش از خاموش‌کردن دکان
      ↓
ج) خاموش‌کردن Min Max  ← تصمیمِ مستقل، حکمش جدا
      ↓
چ) خاموش‌کردن دکان  ← ⛔ از اینجا به بعد تأییدِ سوابق ممکن نیست
      ↓
ح) بازکردنِ فروش، فروشگاه‌به‌فروشگاه  ← تصمیمِ صریحِ هر فروشگاه
      ↓
خ) اولین پرداخت واقعی، با نظارت
```

⛔ **گام «ت» پس از «چ» ممکن نیست**، و این تنها ترتیبِ اجباریِ این فهرست است.

## ۲. گام‌به‌گام

### الف) پشتیبان

| چه چیزی | شرط خروج |
|---|---|
| دیتابیس کامل + پوشهٔ `wp-content` | فایل گرفته شده، **و بازگردانی‌اش روی یک محیط دیگر آزموده شده** |
| تاریخ و ساعت ثبت‌شده | نوشته شده، نه به‌خاطر سپرده |

⛔ **پشتیبانِ نیازموده پشتیبان نیست**، و این تنها گامی است که اگر رد شود
هیچ گام بعدی راهِ برگشت ندارد.

### الف-۲) توقف کنترل‌شدهٔ فروش — ⛔ با مکانیزم خودش

| | |
|---|---|
| **چطور** | صفحهٔ «وضعیت فروش بازارگاه» → توقف فروش |
| ⛔ **و نه با غیرفعال‌سازی افزونه** | `DeactivationStopPolicy` یک پاسخِ ذخیره‌شده است با **پیش‌فرض «نه»**، پس غیرفعال‌سازی فروش را متوقف **نمی‌کند**؛ و اگر «بله» داده شده باشد، محصولات را `draft` می‌کند و فعال‌سازی دوباره **برنمی‌گرداند** |
| **شرط خروج** | صفحه می‌گوید فروش بسته است، و تعدادِ **باقی‌مانده** صفر است (`stopAsResult()` روی فروشگاهی با بیش از `SCAN_LIMIT` محصول باقی‌مانده را **می‌شمارد و می‌گوید**) |
| **برگشت** | «از سرگیری فروش»، یک دکمه |

### ب) نصب `alpha.103`

| | |
|---|---|
| **چطور** | از **پنل افزونه‌ها**، نه FTP — تا دروازهٔ ارتقا در درخواست مدیرِ بعدی بدواند |
| **نتیجهٔ انتظاری** | فعال · صفحهٔ «سلامت» ساختار **۳۹** · هیچ اعلان خطا |
| **چه چیزی جابه‌جا می‌شود** | ⛔ **هیچ‌چیز.** این دور migration ندارد و نصب هیچ مالکیت، وضعیت، قیمت یا موجودی را عوض نمی‌کند |
| **شرط توقف** | هر فاتال، یا ساختاری غیر از ۳۹ |
| **برگشت** | نصب `alpha.102` از همان پنل. **هیچ کار دیتابیسی لازم نیست**؛ بهایش در `ROLLBACK-AND-RECOVERY-FA.md` |

⛔ **و به‌روزرسانی عادی هیچ‌وقت به کدِ غیرفعال‌سازی نمی‌رسد**
(`class-plugin-upgrader.php:581-583`: افزونه **silent** غیرفعال می‌شود و با
`$silent` هیچ قلابِ غیرفعال‌سازی اجرا نمی‌شود). پس نصب ۱۹۷ محصول را
پیش‌نویس نمی‌کند — **و اگر روی غیرفعال‌سازی به‌عنوان «توقف ایمن» حساب کرده
بودید، به‌روزرسانی آن توقف را انجام نمی‌دهد.**

### پ) پیش‌پرواز

`PRODUCTION-PREFLIGHT-FA.md`، هر شانزده ردیف. **شرط خروج: هر شش شرطِ بند ۴
آن سند.** فقط خواندن؛ راهِ برگشت ندارد چون چیزی عوض نمی‌کند.

### ت) تطبیق مالی و تأییدِ سوابق

| | |
|---|---|
| **چطور** | دو ابزار §۳، بعد صفحهٔ «تحویل مهاجرت» برای هر فروشگاه |
| **شرط خروج** | هر شش شرطِ `FINANCIAL-RECONCILIATION-FA.md` بند ۴ |
| **چه چیزی نوشته می‌شود** | **یک ردیف تأیید** به ازای هر فروشگاه، در جدول خودش، با تاریخچه و **قابل ابطال** |
| **چه چیزی نوشته نمی‌شود** | ⛔ هیچ مبلغ، هیچ مالکیت، هیچ اجازهٔ فروش. و ⛔ **هیچ ردیف مالی تاریخی حذف نمی‌شود** |
| **برگشت** | «لغو تأیید» روی همان صفحه. تاریخچه می‌مانَد |

⛔ **و این گام باید پیش از خاموش‌کردن دکان انجام شود**، وگرنه برای همیشه
`dokan_not_running` می‌شود.

### ث) انتقال مالکیت، دسته‌دسته

| | |
|---|---|
| **چطور** | صفحهٔ انتقال، دستهٔ **۲۵**تایی، با دکمهٔ صریح |
| **شرط خروج هر دسته** | فهرستِ جامانده خالی · هیچ `conflict` · هیچ محصولِ تکراری |
| **ایمنیِ ساختاری** | `ApplyOwnershipTransfer` هر محصول را با **آرایهٔ رضایتِ خالی** منتقل می‌کند، پس بدترین کارِ یک ردیفِ اشتباه‌دسته‌بندی‌شده **ایستاندنِ دسته** است |
| **و فهرست در لحظهٔ اعمال دوباره خوانده می‌شود** | فهرستی که تکان خورده `plan_moved` می‌گیرد و **کلِ** دسته رد می‌شود؛ زیرمجموعه **رد می‌شود نه فیلتر** |
| **برگشت** | «پس‌دادن مالکیت» روی همان صفحه. ⛔ یک **واحد کار** است: نوشتنِ اول پس گرفته می‌شود و جواب می‌گوید واقعاً پس رفت یا نه |
| **شرط توقف** | هر `ownership_stamp_unrestored` — یعنی دو نیمه نمی‌خوانند و **یک انسان** باید نگاه کند |

⛔ **و `post_author` عوض نمی‌شود، به‌عمد.** پس پس از انتقال، دکان همچنان آن
محصول را مالِ فروشندهٔ دکان می‌داند — و تا دکان روشن است فروشی ثبت نمی‌شود،
که همان محافظ است.

### ث-۲) تصمیم پوشش کمیسیون — ⛔ تازه، و پیش از بازکردن فروش

| | |
|---|---|
| **چرا** | این افزونه **فقط** `_tmc_commission_type`/`_tmc_commission_value` را می‌خواند و در کلِ `src/` **صفر** ارجاع به کلید کمیسیون دکان است؛ و «بدون کمیسیون» یک **نتیجه** است نه یک رد. پس محصولی که کمیسیونش فقط در متای دکان است، پس از خاموشی با **صفر** فروخته می‌شود — بی خطا و با دفترکل متوازن |
| **چطور** | `wp eval-file tools/production-audit.php products`، بخش «commission» |
| **چه چیزی می‌خوانید** | `commission_uncovered_count` و `commission_uncovered_ids` |
| **شرط خروج** | یا `commission_uncovered_count = 0`، یا **برای هر شناسهٔ آن فهرست یک تصمیم ثبت‌شده**: نرخ محصول در پنل، یا «بدون کمیسیون» به‌صراحت |
| **چه چیزی نوشته نمی‌شود** | ⛔ هیچ نرخی خودکار ست نمی‌شود. ابزار فقط می‌خواند |
| **برگشت** | نرخ هر محصول در همان پنل قابل عوض‌شدن است؛ ⛔ ولی **سفارشِ ثبت‌شده با نرخِ همان لحظه ثبت می‌مانَد** (snapshot)، پس تصمیم پیش از فروش ارزان است و بعدش نه |

### ث-۳) ثبت پایهٔ نشانی فروشگاه دکان — ⛔ تازه، و فقط تا وقتی دکان روشن است

| | |
|---|---|
| **چرا** | `DokanUrlRedirects` پایهٔ نشانی را از `dokan_general` می‌خواند، و **حذف** دکان آن ردیف را پاک می‌کند. از `alpha.102` یک **snapshot** گرفته می‌شود، ولی **فقط از درخواست صریح مدیر** — خواندنی که در هر بازدید بنویسد خواندن نیست |
| **چطور** | صفحهٔ «تحویل مهاجرت»، دکمهٔ ثبت پایهٔ نشانی |
| **شرط خروج** | پایه ثبت شده و روی صفحه دیده می‌شود |
| **برگشت** | دوباره ثبت‌کردنش، تا وقتی دکان روشن است |

### ج) خاموش‌کردن Min Max

| | |
|---|---|
| **پیش‌نیاز** | حکم `permitted` روی **تولید**، و **صفر** قاعدهٔ `blocked` |
| **چطور** | غیرفعال‌سازی عادی افزونه |
| **شرط خروج** | روی یک محصولِ منتقل‌شده، مجموعهٔ تعدادهای مجاز **بایت‌به‌بایت** همان است که پیش از خاموشی بود |
| **برگشت** | فعال‌سازی دوباره. ⛔ و قاعده‌های منتقل‌شده **برمی‌گردند** با دکمهٔ بازگشتِ خودش، نه با حذف |
| **ریسک** | مجوزِ اعمال، اثرانگشتِ **همان سه مقدار** است؛ قاعده‌ای که بعدش عوض شود مجوز را **زنده و مرده** می‌گذارد و صفحهٔ سلامت فهرستش می‌کند |

⛔ **و غیرفعال‌سازی حذف فایل و پاک‌سازی داده نیست.** پاک‌سازیِ دادهٔ Min Max
**جزء این مرحله نیست** و تصمیم جداگانه دارد.

### چ) خاموش‌کردن دکان

| | |
|---|---|
| **پیش‌نیاز** | گام «ت» تمام شده — ⛔ **هر فروشگاه تأیید سوابق دارد** |
| **چطور** | غیرفعال‌سازی Pro، بعد Lite |
| **شرط خروج** | شش صفحهٔ اصلی باز می‌شوند · `DokanUrlRedirects` کار می‌کند (پایه‌اش از `alpha.102` snapshot می‌شود و با **حذف** ردیف دکان هم زنده می‌مانَد) · هیچ ۴۰۴ تازه‌ای روی نشانی فروشگاه‌ها |
| **برگشت** | فعال‌سازی دوباره. ⛔ **دادهٔ دکان دست‌نخورده می‌مانَد** — غیرفعال‌سازی پاکش نمی‌کند، و `data_clear_on_uninstall` را ابزار موجودی می‌خواند |
| **⛔ از این لحظه** | ماژول سفارش ثبت می‌شود و `CaptureOrder` می‌نویسد. پس هر فروشی که از اینجا به بعد بیفتد **سهم ثبت می‌کند** |

⛔ **و غیرفعال‌سازی قاعده‌های rewrite را پاک نمی‌کند.** روی سایتی با پایهٔ
سفارشیِ `store/…` این یعنی نشانی‌های قدیمی زنده می‌مانند و به صفحهٔ اول
می‌رسند — که بدترین حالت است (محتوای تکراری روی ده‌ها نشانی). `alpha.16` همین
را اندازه گرفت، و `DokanUrlRedirects` دقیقاً برای بعدِ همین لحظه است.

### ح) بازکردن فروش، فروشگاه‌به‌فروشگاه

| | |
|---|---|
| **چطور** | `DecideImportedShopSelling` روی صفحهٔ «تحویل مهاجرت»، یک تصمیمِ صریح به ازای **هر** فروشگاه |

| **شرط خروج** | برای **همان** فروشگاه: فهرست محصولاتش درست · ماندهٔ تأییدشده · حکم Min Max `permitted` |
| **برگشت** | «لغو اجازهٔ فروش». ⛔ **هیچ محصولی پیش‌نویس نمی‌شود** — `can_sell = false` از قبل خرید را `vendor_stopped` رد می‌کند |

⛔ **و مجوزش `tmc_review_vendor` است و مجوز تازه‌ای برایش مینت نشد**: نتیجه‌اش
بایت‌به‌بایت همان نوشتنِ `can_sell` ِ تأییدِ درخواست است، و دو کلید برای یک در
یعنی می‌شود بی‌آنکه بخواهید یکی را داد و آن یکی را گرفت.

### خ) اولین پرداخت واقعی

⛔ **تنها با اجازهٔ صریح شما، و روی یک سفارشِ کوچکِ کنترل‌شده.** دوازده
سناریوی `ZARINPAL-PAYMENT-TEST-FA.md`، به همان ترتیب، و **سناریوی دوازدهم
(استرداد) جداگانه اجازه می‌خواهد**.

| شرط خروجِ کل این گام | |

| حالت نامعلوم ⇒ **ایستادن**، نه شارژ دوباره | ⛔ این مهم‌ترین ردیف است |

## ۵. ⛔ پنجرهٔ نظارت ۲۴ تا ۷۲ ساعت — تازه
