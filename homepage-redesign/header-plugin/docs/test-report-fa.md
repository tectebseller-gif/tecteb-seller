# گزارش آزمون — tecteb-header 0.2.1

همهٔ آزمون‌ها روی **وردپرس یکبارمصرف محلی** اجرا شدند: WordPress 7.1، **WooCommerce 11.0.1 ِ واقعی**
(همان نسخهٔ Staging)، Hello Elementor 3.5.1، PHP 8.3.6 با WP_DEBUG، MariaDB، Chromium (Playwright) و
axe-core. Elementor Pro اجرا نشد (نصب افزونهٔ بیرونی اجازه داده نشد)؛ مکان header/footer ِ Theme
Builder با **شبیه‌سازی خط‌به‌خط از کد Pro Elements 4.2.2** ساخته شده (`tests/fixtures/elementor-location-emulator.php`،
از این دور با `did_location()` ِ همان کلاس). جزئیات محیط: `evidence/environment.txt`.
**هیچ کاری روی Staging یا Production انجام نشد.**

## پوشش پنج بند درخواست

1. **نقص دو هدر.** آزمون بازتولید نگه داشته شد: شنونده‌ای روی `PHP_INT_MAX` ِ `before_do_header` که پس
   از افزونه سند ۲۶۵۲ یا ۲۶۵۴ را دوباره به صف می‌افزاید. روی کد 0.2.0 (از git `299d804`) سه بررسی رد شد؛
   روی 0.2.1 همه قبول: **دقیقاً یک هدر** — هدر Elementor — و توضیح `elementor_printed`. مکانی که پیش‌تر در
   همان درخواست چاپ شده ⇒ `elementor_printed_before`، باز یک هدر. مسیر عادی همچنان جایگزین می‌کند.
   هیچ حالتی صفر هدر نمی‌دهد. دو جهش (برداشتن هر کدام از دو گارد) گرفته شدند.
2. **CSS ِ سراسری و فایل‌های ۲۶۵۲.** اندازه‌گیری‌شده، نه حدس: با انتخابگرهای واقعی Kit ِ Elementor 4.2.3،
   `frontend.min.css` ِ واقعی آن و الگوهای رایج Custom CSS، 0.2.0 در ۴۶۹ جا عوض می‌شد (ارتفاع نوار ۱۲۲ ⇒
   ۲۷۹). اصلاح اثبات‌پذیر: پیشوند `#tth-root` و لایهٔ `all: revert` با تبدیل بی‌دست (`tools/harden-css.py`،
   سنجیده در ساخت و آزمون ایستا) ⇒ ۰ تفاوت، و ظاهر برابر نمونه. CSS ِ ۲۶۵۲ dequeue **نشد** (اثبات‌پذیر
   نیست که بقیهٔ صفحه به آن نیاز ندارد)؛ ابزار بررسی قاعده‌های سراسری‌اش را فهرست می‌کند. آنچه پوشش
   داده نمی‌شود: `risks-fa.md` ردیف ۱۷.
3. **سازگاری.** WooCommerce 11.0.1 واقعی؛ Elementor Pro 4.2.2 از کد و شبیه‌ساز؛ CSS ِ Elementor 4.2.3 ِ
   واقعی؛ WP Rocket با کتابخانهٔ Minify ِ خودش و بدل پاک‌سازی؛ PHP 8.1 با PHPCompatibility. جدول اجراشده/
   اجرانشده: `compatibility-review-fa.md` بند ۰-ج.
4. **ابزار بررسی فقط‌خواندنی ۲۶۵۲.** `tools/inspect-header-template.php` (WP-CLI، افزونه لازم نیست فعال
   باشد) و همان گزارش در پیشخوان. آزموده روی یک ۲۶۵۲ ِ ساختگی: انواع ابزارک، JetMenu/html/سبد/shortcode با
   مسیرشان، `<script>`، Popup، sticky، motion، Custom CSS ِ عنصر و قالب، قاعده‌های بی‌محدودهٔ `post-2652.css`
   و `!important`، قلاب‌ها با فایل:خط، و فقط کلیدهای مجاز WP Rocket (کلید محرمانهٔ کاشته‌شده چاپ نشد).
   **هیچ نوشتنی**: پست‌ها، متاها، دسته‌ها، option ها و فایل‌های uploads با تاریخ تغییر پیش و پس یکسان؛
   آزمون ایستا نبودِ هر تابع نوشتن، پاک‌سازی کش و اجرای قلاب را در این دو فایل می‌سنجد. دستورالعمل بی
   بارگذاری هیچ فایل: `inspect-2652-fa.md` راه ب.
5. **تحویل.** `dist/tecteb-header-0.2.1.zip`، `dist/SHA256SUMS`، همین گزارش، `staging-checklist-fa.md`
   (نصب، تست و بازگشت) و `migration-rollback-fa.md`.

## تازه‌های سوییت‌ها در این دور
- یکپارچه: ۴ بررسی بازتولید دو هدر + ۱۵ بررسی ابزار بررسی (خواندن، CLI، json، پیشخوان، بی‌نوشتن، قالب غایب).
- ایستا: `header.css` = خروجی `harden-css.py`؛ لایهٔ ایزوله پیش از قاعده‌ها؛ `id="tth-root"`؛ همهٔ
  انتخابگرها زیر `#tth-root.tecteb-header-v1`؛ ابزار بررسی بی نوشتن، بی پاک‌سازی، بی ساختن پوشه، فقط در WP-CLI.
- `tests/isolation.mjs` (با `MINIFIED=1` برای CSS ِ کوچک‌شده) و `tests/prototype-parity.mjs`.
- Falsification: ۷ جهش تازه (دو گارد دو هدر، لایهٔ ایزوله، id ِ ریشه، نوشتن/ساختن پوشه/چاپ تنظیمات کامل WP Rocket در ابزار).
