**وضعیت:** آماده‌سازی فنی، **نه اجرا.** هیچ نصب، تغییر، انتشار یا اجرای آزمایشی روی

## ۰. خلاصه در شش خط

1. **روش پیشنهادی اتصال:** یک افزونهٔ کوچکِ مستقل و فقط‌خواندنی (`tecteb-homepage`) با
   پنج shortcode، که داده را فقط از API عمومی ووکامرس می‌خواند و CSS/JS را فقط در
   صفحهٔ اصلی بارگذاری می‌کند. **جدا از Tecteb Marketplace**، و بی هیچ تماسی با دکان.
2. **انتخاب از داخل مدیریت ووکامرس:** محصولات = ستارهٔ «ویژه»؛ دسته‌ها = ترتیب
   کشیدنی خودِ ووکامرس؛ تصویر و توضیح دسته = فیلدهای خودِ ووکامرس. هیچ تنظیم تازه‌ای
   لازم نیست (بند ۵).
3. **سازگاری با Hello Elementor:** سورس رسمی همان نسخه (۳٫۵٫۱) خوانده و نشتش
   **اندازه‌گیری شد**: ۵ ویژگی از reset ِ قالب به جست‌وجو و دکمه نشت می‌کند، و ۱۳ ویژگی
   اگر kit ِ Elementor استایل فرم/عنوان داشته باشد. فهرست سخت‌سازی در بند ۳٫۳.
4. **دکان:** هیچ وابستگی؛ تنها نقطهٔ تماس ممکن، نشانیِ دکمهٔ «همکاری تأمین‌کنندگان»
   است که **قابل‌تنظیم** و **به ازای محیط** می‌شود (staging و production فرق دارند).
5. **Staging:** از این محیط **دسترسی ندارم** (سیاست شبکه `tecteb.com` و
   `staging.tecteb.com` را مسدود می‌کند و هیچ credential ای نیست). بکاپ و اجرا با شما
   یا با دسترسی‌ای است که صریحاً بدهید.
6. **روش بازگشت:** صفحهٔ تازه **کنار** صفحهٔ فعلی ساخته می‌شود و فقط
   «تنظیمات ← خواندن ← صفحهٔ اصلی» عوض می‌شود؛ برگشت = برگرداندن همان یک تنظیم و
   پاک‌کردن کش (کمتر از ۵ دقیقه).

## ۲. اتصال واقعی جست‌وجو، دسته‌ها و محصولات به WooCommerce

HTML/CSS به‌تنهایی از ووکامرس نمی‌خواند. سه راه سنجیده شد:

| | الف. افزونهٔ کوچکِ مستقل (**پیشنهادی**) | ب. بدون کد: ویجت HTML + shortcode های ووکامرس | ج. ویجت‌های Elementor Pro / JetWooBuilder |
|---|---|---|---|
| ظاهر کارت | **دقیقاً Concept C** | خروجی loop ِ ووکامرس (`ul.products li.product`)؛ چیپ مشخصات، «استعلام سازمانی» و جای برچسب‌ها **از دست می‌رود** | به طراحی ویجت محدود است |
| خطر دکان | **صفر**: هیچ قلاب loop ِ ووکامرس صدا زده نمی‌شود | ⚠️ loop قلاب‌های `woocommerce_*_shop_loop_item*` را اجرا می‌کند و هر افزونه‌ای (از جمله دکان) می‌تواند در کارت چیزی بنویسد — روی staging باید دید | به همان قلاب‌ها وابسته است |
| وابستگی تازه | یک افزونهٔ کوچک (نصب = تأیید شما) | هیچ | وابستگی به Pro/JetWooBuilder |
| بارگذاری CSS | فایل جدا، فقط در صفحهٔ اصلی، کش مرورگر | `<style>` درون صفحه (~۴۸KB خام، بی کش مرورگر) | — |
| تغییر از مدیریت ووکامرس | ✅ | ✅ | ✅ |

### ۲٫۱ طرح افزونهٔ `tecteb-homepage` (پیشنهادی — ساخته نشده)

- **مستقل:** نه بخشی از Tecteb Marketplace، نه از قالب. در مخزن جدا یا پوشهٔ جدا
  (`homepage-redesign/plugin/`) با ZIP و `SHA256SUMS` خودش. غیرفعال‌کردنش هیچ داده‌ای
  پاک نمی‌کند (هیچ داده‌ای نمی‌نویسد).
- **فقط‌خواندنی:** هیچ `update_*`/`wp_insert_*`/`save()` ای؛ فقط
  `wc_get_products()`، `get_terms('product_cat')`، `get_term_link()`،
  `wc_get_page_permalink()`، `get_price_html()`، `wp_get_attachment_image()`.
- **پنج shortcode، به ترتیب پنج بخش**، هر کدام در یک ویجت Shortcode ِ Elementor:
  `[tecteb_home_hero]` · `[tecteb_home_categories]` · `[tecteb_home_products]` ·
  `[tecteb_home_services]` · `[tecteb_home_suppliers]`. بخش‌های ۴ و ۵ متن ثابت دارند؛
  می‌توانند به‌جای shortcode ویجت HTML ِ Elementor باشند تا ویرایش متن نیاز به کد نداشته
  باشد (تصمیم D1).
- **جست‌وجو:** `<form role="search" action="<?= esc_url(home_url('/')) ?>">` با `s`،
  `post_type=product` و `<select name="product_cat">` (slug واقعی، `esc_attr`).
  ⚠️ جست‌وجوی پیش‌فرض وردپرس/ووکامرس **کد کالا (SKU) و برند را نمی‌گردد**؛ متن کادر
  همین را رعایت کرده («نام محصول»).
- **صفحهٔ نتایج جست‌وجو** قالب آرشیو فعلی سایت است (Hello/Elementor/JetWooBuilder) و
  این طرح آن را **عوض نمی‌کند** — یعنی کاربر از Hero جدید به صفحهٔ نتایجِ طراحی فعلی
  می‌رود. (D13)
- **کش:** هیچ کش داخلی (چهار محصول و هشت ترم، کوئری سبک است)؛ کش صفحه با LiteSpeed.
  ⚠️ تغییر «ویژه» با ستارهٔ فهرست محصولات از راه AJAX ِ ووکامرس انجام می‌شود و ممکن است
  قاعدهٔ پاک‌سازی خودکار LiteSpeed را راه نیندازد ⇒ افزونه روی
  `woocommerce_update_product`، `edited_product_cat` و تغییر موجودی، فقط نشانی صفحهٔ
  اصلی را با `do_action('litespeed_purge_url', home_url('/'))` پاک کند (اگر LiteSpeed
  نصب نباشد، این قلاب کاری نمی‌کند).

علتِ دومی **specificity** است: Elementor برای فیلدهای فرم انتخابگرِ
`.elementor-kit-N input:not([type="button"]):not([type="submit"])` می‌سازد که (0,3,1)
است و از (0,3,0) ِ ما **قوی‌تر**. kit ِ سایت را ندیده‌ام؛ اگر Site Settings ِ Elementor
برای فرم یا عنوان چیزی تنظیم نکرده باشد، این نشت رخ نمی‌دهد — ولی سخت‌سازی ارزان است.

### ۳٫۳ سخت‌سازی لازم پیش از اجرا (در CSS تولید)

1. کنترل‌ها را **صریح** بنویسیم، با انتخابگر (0,4,0):
   `.tecteb-home-v1.th-c .th-search .th-search__input { padding:0; border:0; border-radius:0; background:transparent; inline-size:auto; transition:none; box-shadow:none }`
   و همین برای `select` (`padding-block:0`) و `.th-btn` (`padding-block:0`).
2. در reset ِ داخلی (`:where(h1,h2,h3,p,…)`): `font-weight`، `text-transform:none`،
   `letter-spacing:normal`، `font-style:normal` و `line-height`.
3. `:focus-visible` ِ Hello یک `box-shadow: 0 0 0 4px #fff` هم اضافه می‌کند؛ روی
   Hero تیره یک حلقهٔ سفید کنار حلقهٔ فیروزه‌ای ما می‌سازد. یا صریح `box-shadow` خودمان را
   بدهیم، یا بپذیریم (دسترس‌پذیرتر است). پیشنهاد: بپذیریم، با یک بررسی چشمی.
4. آزمون بند ۹ همین اسکریپت را روی **صفحهٔ واقعی staging** هم اجرا می‌کند.

### ۳٫۴ جای‌گذاری در Elementor

- **صفحهٔ تازه** (نه ویرایش صفحهٔ فعلی) با قالب صفحهٔ **«Elementor Full Width»** (هدر و
  پاورقی سایت می‌ماند). **«Elementor Canvas» نه** — هدر و پاورقی را حذف می‌کند.
- **«Hide Title» روشن:** Hello Elementor عنوان صفحه را به‌صورت `h1` چاپ می‌کند؛ بی این،
  صفحه دو `h1` دارد.
- یک Container تمام‌عرض با padding و gap ِ صفر، و پنج ویجت Shortcode/HTML پشت سر هم.
  ریشهٔ `.tecteb-home-v1` خودش `container-type: inline-size` است، پس داخل ستون Elementor
  هم درست می‌شکند.
- **سازگاری مرورگر:** container query (Chrome 105+، Safari 16+، Firefox 110+)؛ مرورگر
  قدیمی‌تر چیدمان موبایل را می‌بیند (کامل، فقط تک‌ستون). `:has()` فقط برای پنهان‌کردن یک
  خط تزئینی است. `animation-timeline` فقط Chromium؛ بقیه بی‌حرکت و کامل.
- **ناشناخته‌ها (D14):** Elementor Pro نصب است؟ هدر/پاورقی از Theme Builder است یا از
  خودِ Hello؟ هدر چسبان است (روی Hero می‌افتد)؟ فونت سایت چیست (D2)؟

## ۴. دکان و مهاجرت به Tecteb Marketplace

- **کد:** Concept C هیچ shortcode، تابع، کلاس، جدول یا نشانیِ ثابتِ دکان ندارد؛ افزونهٔ
  پیشنهادی هم نخواهد داشت، و چون loop ِ ووکامرس را صدا نمی‌زند، هیچ خروجیِ قلاب‌شدهٔ دکان
  (مثل «فروشنده: …») در کارت‌ها ظاهر نمی‌شود. یک آزمون معماری همین را از بایت‌های افزونه
  می‌سنجد (بند ۹: «هیچ `dokan`»).
- **مهاجرت:** داده فقط از ووکامرس است. خواندن کد Tecteb Marketplace (فقط‌خواندنی) نشان
  داد پروژکتورش `catalog_visibility` را برای محصول منتشرنشده `hidden` می‌کند
  (`WooCommerceProjector.php:211` و `:452`) و **پرچم «ویژه» را هیچ‌جا نمی‌نویسد**. پس:
  - کوئری صفحهٔ اصلی باید `visibility => 'catalog'` و `status => 'publish'` بگیرد؛ آن وقت
    محصولی که بازارگاه پنهان کرده، در صفحهٔ اصلی هم پنهان است — رفتار درست، بی هماهنگی.
  - «ویژه» بودن یک محصول با واردشدنش به بازارگاه از دست نمی‌رود (شناسهٔ ووکامرس عوض
    نمی‌شود). ⚠️ این‌که `save()` ِ پروژکتور پرچم را نگه می‌دارد رفتار ووکامرس است، نه کدِ
    ما — روی staging سنجیده شود (بند ۹).
- **تنها نقطهٔ تماس: دکمهٔ «همکاری تأمین‌کنندگان».** مسیر درخواست فروشندگی Tecteb
  Marketplace `/vendor/application/` است (`VendorRoutes.php:243`) و **فقط جایی که آن
  افزونه نصب است** وجود دارد. طبق اسناد همین مخزن، staging نسخهٔ `alpha.78` را دارد و
  سایت اصلی ندارد ⇒ روی production این نشانی ۴۰۴ است. پس نشانی **یک تنظیم** است
  (گزینهٔ افزونه یا ویرایش ویجت)، نه کد: امروز = ثبت‌نام فعلی (دکان)، پس از مهاجرت =
  `/vendor/application/`. عوض‌کردنش یک ویرایش است، نه نسخهٔ تازه. (D7)

## ۷. Staging، بکاپ، بازگشت و ریسک‌ها

### ۷٫۱ وضعیت دسترسی

- **از این محیط هیچ دسترسی به Staging یا Production ندارم.** سیاست شبکه اتصال به
  `tecteb.com` و `staging.tecteb.com` را رد می‌کند (اندازه‌گیری‌شده در دور ۱) و هیچ
  نام‌کاربری، کلید یا SSH ای در اختیار ندارم. **هیچ ادعایی دربارهٔ وضعیت فعلی staging در
  این گزارش «دیده‌شده» نیست**؛ هرچه آمده از اسناد همین مخزن است (گزارش مالک).
- دو راه: (۱) شما گام‌ها را اجرا کنید و من چک‌لیست و تصویرها را بررسی کنم؛ یا (۲)
  دامنهٔ staging را به «Allowed domains» این محیط اضافه کنید **و** یک حساب مدیر
  staging ِ موقت و محدود بدهید. حتی در حالت (۲) فقط آنچه تأیید کنید انجام می‌شود.

### ۷٫۲ پیش‌نیازهای بکاپ (پیش از هر تغییری روی staging)

1. **بکاپ کامل** فایل‌ها + دیتابیس از سطح میزبان (یا افزونهٔ بکاپ موجود)، با تاریخ و
   **آزمودن بازگردانی** آن (یک بکاپ آزموده‌نشده بکاپ نیست).
2. **صادرکردن صفحهٔ اصلی فعلی:** Elementor ← Templates ← Save as template ← Export (JSON).
3. ثبت **شناسه‌ها:** شناسهٔ صفحهٔ اصلی فعلی (تنظیمات ← خواندن)، شناسهٔ kit ِ Elementor،
   قالب صفحهٔ فعلی.
4. **خروجی تنظیمات LiteSpeed Cache** (Toolbox ← Import/Export) و تنظیمات Rank Math برای
   صفحهٔ اصلی (عنوان، توضیح، canonical، schema).
5. تصویر کامل دسکتاپ و موبایل و Lighthouse صفحهٔ فعلی (خط مبنا — بند ۹٫۱).

### ۷٫۳ روش بازگشت (سه لایه)

1. **فوری (کمتر از ۵ دقیقه):** تنظیمات ← خواندن ← صفحهٔ اصلی = صفحهٔ قبلی، سپس پاک‌کردن
   کش LiteSpeed. صفحهٔ قبلی دست‌نخورده است، چون صفحهٔ تازه **کنار** آن ساخته شده.
2. **غیرفعال‌کردن افزونهٔ `tecteb-homepage`:** هیچ داده‌ای پاک نمی‌شود و جای دیگری از سایت
   از آن استفاده نمی‌کند.
3. **آخرین راه:** بازگرداندن قالب JSON ِ Elementor یا بکاپ کامل.

صفحهٔ قبلی تا دست‌کم دو هفته پس از انتشار حذف نشود.

## ۸. اجرای ایزولهٔ CSS/JS و بارگذاری تصاویر

### ۸٫۱ ساختار افزونه (پیشنهادی)

```
tecteb-homepage/
  tecteb-homepage.php        بارگذار؛ shortcode ها؛ enqueue فقط در صفحهٔ اصلی
  src/                       خواننده‌های فقط‌خواندنی + رندر (escape کامل)
  templates/                 HTML پنج بخش (همان markup ِ Concept C)
  assets/css/home.css        concept-c.css منهای قواعد پیش‌نمایش + سخت‌سازی ۳٫۳
  assets/js/home.js          concept-c.js (۱٫۳KB، اختیاری)
  assets/img/                رندر Hero (۷۲۰/۱۲۰۰ WebP)، لوگوی ۹۶px، آیکون‌های پیش‌فرض
  assets/fonts/              Vazirmatn + OFL.txt — فقط اگر D2 «نگه‌داشتن» باشد
```

### ۸٫۲ قواعد

- **بارگذاری شرطی:** `wp_enqueue_style('tecteb-home', …, [], VERSION)` و
  `wp_enqueue_script('tecteb-home', …, [], VERSION, ['strategy' => 'defer', 'in_footer' => true])`
  فقط وقتی `is_front_page()` یا صفحه shortcode ما را دارد. نسخه در نشانی برای شکستن کش.
- **دامنه:** همهٔ قواعد زیر `.tecteb-home-v1.th-c`؛ هیچ انتخابگری روی `body`، `header`،
  `footer`، `.elementor`، `.woocommerce` یا `.dokan` (آزمون ایستای موجود همین را می‌سنجد)؛
  تنها قاعدهٔ سراسری `@font-face` با نام یکتای «TH Vazirmatn».
- **JS:** یک IIFE، فقط روی `[data-th-light]` داخل `.tecteb-home-v1`؛ بدون وابستگی، بدون
  jQuery، بدون درخواست شبکه؛ با اشاره‌گر لمسی و «کاهش حرکت» اجرا نمی‌شود.
- **هیچ درخواست بیرونی:** نه Google Fonts، نه CDN، نه ردیاب.
- **تصاویر:**
  - Hero: `<picture>` با WebP ِ ۷۲۰ (موبایل) و ۱۲۰۰ (دسکتاپ)، `width/height`،
    `fetchpriority="high"`، **بدون lazy** و استثناشده از lazyload ِ LiteSpeed.
  - محصول و دسته: `wp_get_attachment_image()` با اندازهٔ `woocommerce_thumbnail` (یا
    `thumbnail` برای دسته) ⇒ `srcset` و `sizes` خودِ وردپرس، `loading="lazy"`،
    `width/height` (بی جابه‌جایی چیدمان).
  - لوگو: PNG ِ ۹۶px (یا SVG اگر برسد — D16).
- **بودجهٔ وزن (اندازه‌گیری‌شده روی پیش‌نمایش):** HTML ۵٫۷KB + CSS ۱۰KB + JS ۰٫۷KB
  (gzip)، Hero ۴۵/۵۴KB، هر تصویر محصول ۱۰ تا ۲۰KB، لوگو ۱۰KB، فونت ۱۱۱KB.

**سئو**
14. عنوان، توضیح، canonical و schema ِ صفحهٔ اصلی همان مقادیر تأییدشده؛ صفحهٔ تازه پیش از
    تعویض نمایه‌پذیر نیست.

**رگرسیون**
15. تکرار آزمون دود ۹٫۱-۸؛ لاگ PHP و کنسول بی خطای تازه.

**بازگشت**
16. **تمرین بازگشت** روی staging: برگرداندن صفحهٔ اصلی و پاک‌کردن کش ⇒ صفحهٔ قبلی، زمان‌گرفته.

### ۹٫۴ پس از تعویض صفحهٔ اصلی روی staging

تکرار ۱ تا ۱۵ برای کاربر واردنشده و از پشت کش، به‌علاوهٔ مقایسهٔ Lighthouse با خط مبنا.
