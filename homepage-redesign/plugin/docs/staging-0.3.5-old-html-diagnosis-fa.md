# Staging: افزونه 0.3.5 فعال است ولی HTML ِ 0.3.4 دیده می‌شود — تشخیص

**وضعیت:** فقط بررسی. هیچ نسخه‌ای ساخته نشد و هیچ تغییری روی Staging یا Production انجام نشد. این جلسه به
staging.tecteb.com دسترسی شبکه ندارد (پراکسی اتصال را رد می‌کند)، پس صفحهٔ Staging از اینجا خوانده نشد.

## آنچه از کد اثبات می‌شود
1. `templates/products.php` داخل `tecteb-homepage-0.3.5.zip` (SHA-256 `74499987…fa80`) **هیچ** `th-filter` یا `th-chip`
   ندارد و سربرگ بخش `th-head th-head--shop th-reveal` است.
2. مسیر رندر فقط یکی است: `Renderer` فایل را از `TECTEB_HOME_DIR . 'templates/products.php'` می‌خواند — پوشهٔ
   همان افزونه‌ای که اجرا شده. هیچ `locate_template`، هیچ بازنویسی از قالب سایت، هیچ کش HTML ِ داخلی (کلاس `Cache`
   فقط کش صفحه را **پاک** می‌کند). ورودی‌ها: گزینهٔ «نمایش روی صفحهٔ نخست» (`template_include` ⇒ `templates/front-page.php`)
   یا کد کوتاه `[tecteb_home]`؛ هر دو همان `Renderer`.
3. Elementor ویجت Shortcode را کش نمی‌کند (`is_dynamic_content()` پیش‌فرض `true`، خوانده از سورس Elementor 4.2.3)،
   و در حالت «صفحهٔ نخست» محتوای Elementor اصلاً رندر نمی‌شود.
4. افزونه در برابر بارگذاری دوگانه گارد ندارد: دو نسخهٔ **فعال** هم‌زمان خطای مرگبار می‌دهند، نه HTML ِ قدیمی.

**پس اجرای کد 0.3.5 نمی‌تواند ردیف فیلتر را چاپ کند.** HTML ِ دیده‌شده از یکی از این‌هاست — و هر کدام ردِ
متفاوتی در فایل‌های عمومی سایت دارد:

| | علت | رد قابل‌سنجش |
|---|---|---|
| A | کش صفحه‌ای بیرون از آنچه پاک شد (کش سرور/میزبان، nginx، LiteSpeed سرور، CDN) | درخواست همان صفحه با یک پارامتر یکتا HTML ِ 0.3.5 دارد؛ نشانی معمولی 0.3.4؛ سربرگ‌های پاسخ HIT/age |
| B | OPcache کهنه (میزبان `opcache_invalidate` ِ وردپرس را با `opcache.restrict_api` یا `disable_functions` بسته) | در HTML ِ تازه، CSS با `?ver=0.3.4` (ثابت نسخه از کد کامپایل‌شدهٔ قدیمی) در حالی که `readme.txt` همان پوشه روی دیسک `0.3.5` می‌گوید |
| C | نسخهٔ دیگری از افزونه در پوشهٔ دیگری اجرا می‌شود | پوشهٔ نشانی CSS (مثلاً `/plugins/tecteb-homepage-xyz/`) غیر از `tecteb-homepage`، و `readme.txt` آن پوشه نسخهٔ قدیمی |
| D | نصب ناقص یا OPcache ِ فقط برخی فایل‌ها | `?ver=0.3.5` و readme 0.3.5، ولی HTML ِ تازه هنوز ردیف فیلتر دارد |

(«فروشگاه» در **دسکتاپ و تبلت** طبق طرح می‌ماند؛ فقط در موبایل پنهان است. ردیف فیلتر نشانهٔ قطعی است.)

## روش تشخیص فقط‌خواندنی (۲ دقیقه، از مرورگر)
صفحهٔ اصلی Staging در پنجرهٔ ناشناس ← DevTools ← Console ← محتوای `tools/diagnose-version.js` را بچسبانید ← Enter.
فقط GET از همان دامنه: صفحه با پارامتر یکتا، `readme.txt` و CSS ِ پوشهٔ افزونه. خروجی JSON و یک `VERDICT` (A تا F) است.
آزموده روی وردپرس محلی: روی 0.3.5 ⇒ E؛ با قالب 0.3.4 ⇒ ردیف فیلتر و حکم D.

مکمل از پیشخوان (فقط دیدن): «افزونه‌ها» — چند ردیف «Tecteb Homepage» هست؟ «ویرایشگر فایل افزونه» (اگر بسته نیست)
← Tecteb Homepage ← `templates/products.php`: آیا `th-filter` دارد؟ (فقط ببینید، ذخیره نکنید.)

## کوتاه‌ترین راه‌حل، بسته به حکم
- **A:** پاک‌سازی همان کشی که سربرگ‌ها نام می‌برند (پنل میزبان/CDN)، فقط برای صفحهٔ اصلی. پاک‌سازی WP Rocket به آن نمی‌رسد.
- **B:** «Flush/Reset OPcache» یا ری‌استارت PHP از پنل میزبان (یا صبر تا `opcache.revalidate_freq`). نیاز به نسخهٔ تازه نیست.
- **C:** غیرفعال‌کردن ردیف قدیمی و فعال‌کردن ردیف `tecteb-homepage` (0.3.5) در «افزونه‌ها». حذف پوشهٔ قدیمی پس از پشتیبان.
- **D:** بارگذاری دوبارهٔ همان `tecteb-homepage-0.3.5.zip` با «جایگزینی» (وردپرس OPcache هر فایل را باطل می‌کند)؛ اگر ماند، مثل B.
