# گزارش نهایی سرعت صفحهٔ نخست تک‌طب — Header 0.2.6 و Homepage 0.3.7

**دامنه:** چرخهٔ کامل بررسی ← ریشه‌یابی ← اصلاح امن ← آزمون رگرسیون ← سنجش سرعت ← بسته‌بندی، فقط در کد دو افزونهٔ
خودمان. **هیچ نصب، به‌روزرسانی، تنظیم یا ذخیره‌ای روی Production (`tecteb.com`) یا Staging انجام نشد؛ هیچ افزونه‌ای
نصب نشد؛ هیچ دسترسی یا رمزی استفاده نشد.** Tecteb Marketplace Core، دکان، دیتابیس، محصولات، دسته‌ها، موجودی، قیمت‌ها،
سفارش‌ها و تنظیمات سایت دست نخوردند.

**از این محیط Production قابل اندازه‌گیری نبود:** اتصال از پروکسی برقرار می‌شود و سرور مبدأ TLS را می‌بندد، و سهمیهٔ
ناشناس PageSpeed API تمام است (۴۲۹). پس **هیچ عددی در این گزارش عدد Production نیست** مگر صریحاً «از گزارش شما» گفته
شود؛ همهٔ اعداد محلی‌اند و هرچه فقط روی سایت واقعی قابل سنجش است **«تأییدنشده»** آمده است.

**بستر سنجش تازه (این دور):** چون سایت محلی قبلی Elementor را شبیه‌سازی می‌کرد و نمی‌توانست صف CSS ِ Production را
بسازد، یک وردپرس یکبارمصرف دوم با **Elementor 4.2.3 و PRO Elements 4.2.2 ِ واقعی** ساخته شد (ووکامرس 11.0.1، Hello
Elementor 3.5.1، هدر Theme Builder ِ «کل سایت» با همان ابزارک‌هایی که در فهرست PageSpeed ِ شما دیده می‌شوند — منوی
ناوبری، جست‌وجو، جعبهٔ آیکون با انیمیشن buzz-out، شبکه‌های اجتماعی، فهرست آیکون، جداکننده، عنوان — فوتر «کل سایت»، و
برگهٔ نخست ساخته‌شده با Elementor). `perf/tools/real-elementor-testbed.php`.

## ۲. علت‌های اثبات‌شده
### ۲-الف. CSS و JS ِ قالب‌هایی که چاپ نمی‌شوند — اثبات‌شده روی Elementor ِ واقعی
وقتی Header B هدر Elementor (قالب «کل سایت»، روی بستر ۲۶۵۲) را جایگزین می‌کند و Tecteb Homepage برگهٔ نخست را،
**Elementor همچنان همهٔ CSS و دارایی‌های آن دو سند را در `<head>` می‌گذارد**، چون تصمیم چاپ‌نکردن بعداً — در لحظهٔ
رندر — گرفته می‌شود. روی بستر با 0.2.5/0.3.6 از ۳۱ فایل CSS ِ `<head>`، **۱۵ فایل** مال این دو سند بود و هیچ چیزی را
روی صفحه نمی‌آراست، به‌اضافهٔ سه JS (`smartmenus`، `swiper`، `jquery-numerator`).

سازوکار، خوانده از سورس Elementor 4.2.3 / Pro 4.2.2 و سنجیده:
1. `Locations_Manager::enqueue_styles` ِ Pro (`wp_enqueue_scripts`، اولویت ۱۰) برای هر سند ِ هر مکان سه کار می‌کند:
   `Post_CSS::enqueue()` (فایل `post-<ID>.css` یا همان CSS به‌صورت درون‌خطی)، فونت‌ها و کتابخانه‌های آیکون ثبت‌شده در
   متای همان CSS (Font Awesome، eicons)، و `handle_page_assets()` که فهرست `_elementor_page_assets` (widget-*،
   e-animation-*، e-apple-webkit، smartmenus، …) را فوراً بارگذاری می‌کند.
2. `Frontend::enqueue_styles` همین سه کار را برای **پست جاری** (`get_the_ID()`) می‌کند — یعنی برای برگهٔ نخست، حتی
   وقتی Tecteb Homepage به‌جایش قالب خودش را چاپ می‌کند؛ و حتی برای برگه‌ای که دیگر با Elementor ویرایش نمی‌شود ولی
   متای `_elementor_page_assets` ِ کهنه دارد (آزموده).
3. در `wp_footer` هر دارایی ِ «فعال‌شده» دوباره enqueue می‌شود، پس `wp_dequeue_style` ِ ساده کافی نبود.

این همان چیزی است که در فهرست PageSpeed ِ شما با نام‌های `widget-image`، `widget-nav-menu`، `widget-search`،
`widget-icon-box`، `widget-social-icons`، `e-animation-buzz-out`، `apple-webkit` (و احتمالاً Font Awesome) دیده
می‌شود؛ **نسبت‌دادن آن نام‌ها روی Production به همین سازوکار محتمل است ولی تأییدنشده**، چون نشانی کامل و محتوای هدر
Production دیده نشد.

### ۲-ب. اندازهٔ اثر — اثبات‌شده روی بستر (نه Production)
- CSS ِ `<head>`: **۳۱ ← ۱۶**؛ JS ِ body: ۱۶ ← ۱۳؛ کل درخواست‌ها ۷۱ ← ۵۳؛ حجم ۴۶۳ ← ۳۹۶ کیلوبایت (موبایل).
- Lighthouse موبایل (میانهٔ ۵): FCP **۲٫۳۳ ← ۲٫۰۱ ثانیه**، LCP **۳٫۷۸ ← ۳٫۵۳**، امتیاز **۸۶ ← ۸۹** — بند ۷.
- Trace ِ واقعی با throttle (Slow 4G، CPU ×۴، کش سرد): FCP ۴٫۶۶ ← ۳٫۵۲، LCP ۴٫۹۲ ← ۳٫۵۲ ثانیه.
- در سه حالت Elementor (فایل CSS، Internal Embedding، آیکون فونتی) `<head>` پس از جایگزینی **دقیقاً** همان است که
  Elementor برای همین صفحه **اگر قالب هدر منتشر نشده بود** بارگذاری می‌کرد — نه کمتر، نه بیشتر (`perf/tests/elementor-modes.sh`،
  ۲۱ از ۲۱). در حالت آیکون فونتی `elementor-icons-fa-brands` و `-fa-regular` (فقط هدر) حذف می‌شوند و `-fa-solid`
  (فوتر هم دارد) می‌ماند.

### ۲-ج. عنصر LCP و اجزای آن (بستر، موبایل)
عنصر LCP در هر ۲۰ اجرای Lighthouse ِ موبایل (قبل و بعد) `span.tth-logo__word` (واژهٔ «تک‌طب» ِ هدر) است — همان بلوک
لوگو که PageSpeed ِ شما `img.tth-logo__mark` نام برده. TTFB ۵–۱۲ms (تصویر لحظه‌ای مثل کش صفحه)، Load delay و Load time
صفر (متن است)، و **Render delay** همهٔ بقیه: یعنی LCP را صف CSS/JS ِ مسدودکننده تعیین می‌کند، نه هدر. در trace ِ
مشاهده‌شده LCP = FCP (~۰٫۳ ثانیه بی throttle)؛ عدد ۳٫۵ ثانیه شبیه‌سازی Lantern است که هر درخواستی را که پیش از آن لحظه
شروع شده (CSSها، jQuery، فونت ۱۰۹KB ِ preload‌شده) روی Slow 4G در مسیر می‌گذارد.

### ۲-د. Forced reflow
در ۱۰ اجرای موبایل ِ 0.2.5/0.3.6 روی بستر: یک اجرا ۴۵ms «unattributed» (بی منبع)، بقیه صفر؛ در 0.2.6/0.3.7 صفر در هر ۵.
هیچ‌کدام به `header.js` یا `tecteb-home.js` نسبت داده نشد. «forced reflow» ِ گزارش شما روی Production **تأییدنشده**
است و اگر stack trace ِ آن را بفرستید قابل نسبت‌دادن است.

### ۲-هـ. یک نقص بستر که اعداد را خراب می‌کرد (نه افزونه‌ها، نه Production)
اولین دور سنجش روی بستر تازه نامعتبر بود: `post-11.css` (Kit) و `hello-frontend.js` روی دیسک نبودند، هر دو با 301 به
صفحهٔ نخست می‌رفتند، و مرورگر یک صفحهٔ کامل را به‌عنوان «stylesheet ِ مسدودکننده» بارگذاری می‌کرد. آن دور کنار گذاشته
شد (`perf/evidence/er-invalid-missing-kit-css/INVALID.txt`)، بستر اصلاح شد، و از این پس `lh-runs.sh` هر درخواست غیر-۲۰۰
را در `bad_requests` گزارش می‌کند — در هر ۲۰ اجرای معتبر: صفر.

- **پیش از** `Locations_Manager::enqueue_styles` ِ Pro (`wp_enqueue_scripts` اولویت ۹): اگر جایگزینی انجام خواهد شد —
  `active()`، و **همهٔ** اسناد هدرِ این صفحه در فهرست قالب‌های انتخاب‌شدهٔ مدیر، و صفحهٔ جاری خودِ آن قالب نیست — فیلتر
  عمومی خودِ Pro (`elementor/theme/get_location_templates/template_id`) برای همان قالب‌ها در مکان header شناسهٔ ۰
  برمی‌گرداند؛ Pro قالب «منتشرنشده» را رد می‌کند و CSS/دارایی‌اش را بارگذاری نمی‌کند.
- **پس از** آن (اولویت ۱۱): فیلتر برداشته و کش مکان‌ها پاک می‌شود؛ پس در لحظهٔ رندر همان قالب دوباره در صف است و
  جایگزینی **دقیقاً مثل 0.2.5** انجام می‌شود. HTML ِ هدر بایت‌به‌بایت همان (آزمون ارتقا).
- **بازگشت ایمن:** اگر به هر دلیل Elementor هدر خودش را چاپ کند (افزونهٔ دیگر قالب را دوباره بیفزاید، تنظیم بین
  `<head>` و هدر عوض شود، …) همان CSS و دارایی‌ها دوباره بارگذاری می‌شوند (`restore_skipped_assets`) — دیرتر و در پایین
  صفحه، ولی هدر Elementor بی‌سبک نمی‌ماند. هر دو حالت روی Elementor ِ واقعی سنجیده شد.
- دارایی‌هایی که سند دیگری (فوتر، Popup، صفحه) لازم دارد دست نمی‌خورند — Pro آن‌ها را برای همان سند بارگذاری می‌کند.
- هیچ `wp_dequeue_*`/`wp_deregister_*`، هیچ Reflection، هیچ نوشتن در دیتابیس.

### Homepage 0.3.7 — `includes/class-page-template.php` (و نسخه در `tecteb-homepage.php` و `readme.txt`)
- وقتی `takes_over_front()` (پس نه در ویرایشگر، پیش‌نمایش، `?tecteb_home_original=1` یا صفحه‌ای دیگر)، پست جاری فقط
  در فاصلهٔ دو قلاب خودِ Elementor — `elementor/frontend/after_enqueue_styles` (آخرین شنونده) تا
  `elementor/frontend/after_enqueue_post_styles` (اولین شنونده) — کنار گذاشته و برگردانده می‌شود؛ میان این دو فقط بلوک
  «CSS و دارایی‌های پست جاری» ِ Elementor اجرا می‌شود. محض احتیاط آخرین شنوندهٔ `wp_enqueue_scripts` هم برمی‌گرداند.
- نتیجه: CSS، فونت‌ها و دارایی‌های ابزارک‌های برگهٔ نخست قدیمی بارگذاری نمی‌شوند؛ صفحهٔ چاپ‌شده بایت‌به‌بایت همان.

**هیچ تغییری در ظاهر، RTL، تایپوگرافی، لوگو، رنگ، فاصله‌ها، Mega Menu، کشوی موبایل، هدر چسبان، جست‌وجو، حساب، سبد،
نوار پایین موبایل، کارت‌های دسته، محصولات، پیوندها یا هر صفحهٔ دیگر.** هیچ CSS ِ سراسری تازه‌ای اضافه نشد.

## ۸. ریسک و سازگاری
- **سازگاری:** Elementor 4.2.3 و PRO Elements 4.2.2 ِ واقعی (هم‌کد با Elementor Pro 4.2.2)؛ فقط API ِ عمومی
  (`elementor/theme/get_location_templates/template_id`، `Conditions_Manager::get_documents_for_location`،
  `clear_location_cache`، `Post_CSS::create()->enqueue()`، `assets_loader->enable_assets()`). اگر هر کدام نبود (نسخهٔ دیگر
  Pro، Pro غیرفعال) کد کنار می‌کشد و رفتار همان 0.2.5 است (`conditions_manager()` ⇒ null).
- **سه حالت چاپ CSS** ِ Elementor (فایل، Internal Embedding، آیکون فونتی) با مرجع دقیق سنجیده شد (۲-ب).
- **مهمان و واردشده:** مدیرِ واردشده همان صفحه را می‌بیند؛ اضافه‌ها فقط نوار مدیریت و `elementor-icons` ِ آن (برای
  «ویرایش با Elementor»).
- **صفحه‌های دیگر:** فروشگاه، سبد، برگهٔ ساده — هدر B، بی دارایی ۲۶۵۲، فوتر کامل. محصول/حساب/تسویه همان مسیر هدر را
  دارند (هدر در همهٔ صفحه‌ها یکی است).
- **ریسک باقی‌مانده:** CSS ِ سفارشی در **Custom CSS ِ خودِ قالب هدر ۲۶۵۲** که برای **عنصر دیگری از صفحه** (نه خودِ هدر)
  نوشته شده باشد، با 0.2.6 بارگذاری نمی‌شود — چون همان CSS ِ همان سند است. روی بستر چنین چیزی نیست؛ روی Production
  **تأییدنشده** است. نشانه: هر عنصری بیرون از هدر که پس از ارتقا سبکش عوض شود. بازگشت: 0.2.5، یا `?tth_original=1`
  برای مقایسه.
- **WP Rocket:** کش صفحه HTML ِ تازه را لازم دارد (`?ver=` ِ `header.css` و `tecteb-home.css` عوض شد)؛ پس از نصب
  «Clear cache». RUCSS/Used CSS ِ ذخیره‌شده هم باید پاک شود.
- **migration:** ندارد. هیچ option، جدول یا متا نوشته یا خوانده‌شدنی تازه‌ای نیست؛ تنظیمات بایت‌به‌بایت (آزموده).

## ۱۰. مواردی که فقط روی Production قابل سنجش‌اند
1. **نشانی کامل و مالک هر فایل فهرست PageSpeed ِ شما** — در PageSpeed، «Render-blocking requests» ← نشانی کامل هر ردیف
   (یا در Chrome: DevTools ← Network ← فیلتر CSS، ستون Initiator). ستون ۳ ِ جدول ۴-الف را تأیید یا رد می‌کند.
2. **اثر 0.2.6/0.3.7 روی Production:** همان ۵ اجرای PageSpeed موبایل و دسکتاپ پس از نصب روی Staging و پاک‌کردن کش؛
   شمارش «Render-blocking requests» قبل/بعد. هر عدد بالای این گزارش محلی است.
3. **محتوای قالب هدر و برگهٔ نخست Production** (کدام ابزارک‌ها) — تعیین می‌کند چند فایل حذف می‌شود.
4. **Custom CSS ِ قالب هدر ۲۶۵۲** — اگر عنصری بیرون از هدر را هدف گرفته (ریسک بند ۸).
5. **تنظیم «Inline Font Icons» و «Improved CSS Loading» ِ Elementor**، و گزینه‌های فعلی WP Rocket (بند ۹).
6. **منبع IRANMarker.ttf و `hamarz/sheyda/fadel*`**.
7. **forced reflow با stack trace** و LCP breakdown ِ مشاهده‌شده در PageSpeed ِ Production.
8. **حالت کش موبایل جدا در WP Rocket** (اگر «Separate cache files for mobile devices» روشن است، HTML ِ موبایل جداگانه کش
   می‌شود و باید هر دو پاک شوند).

## ۱۱. نصب و بازگشت
**ترتیب پیشنهادی — اول Staging:**
1. پشتیبان از فایل‌ها (یا فقط از دو پوشهٔ `wp-content/plugins/tecteb-header` و `tecteb-homepage`). دیتابیس دست نمی‌خورد.
2. افزونه‌ها ← افزودن ← بارگذاری ← `tecteb-header-0.2.6.zip` ← «جایگزینی نسخهٔ فعلی با نسخهٔ بارگذاری‌شده». همین برای
   `tecteb-homepage-0.3.7.zip`. ترتیب مهم نیست؛ هر کدام مستقل است.
3. WP Rocket ← Clear and preload cache (و Clear Used CSS اگر RUCSS روشن است). اگر کش سرور/CDN دارید، آن هم.
4. بازدید مهمان (پنجرهٔ ناشناس) از صفحهٔ نخست، فروشگاه، یک محصول، سبد، حساب در موبایل و دسکتاپ؛ چک‌لیست بند ۱۲.
5. PageSpeed ِ موبایل و دسکتاپ، ۳ تا ۵ بار؛ مقایسه با اعداد پیش از نصب.
6. بررسی سریع مدیر: در کد منبع صفحه (فقط برای مدیرِ واردشده) توضیح
   `<!-- tecteb-header: replaced Elementor header template 2652; its CSS and assets not loaded: 2652 -->` دیده می‌شود.

**بازگشت (هر زمان، بی کار دیتابیسی):** همان مسیر با `tecteb-header-0.2.5.zip` و `tecteb-homepage-0.3.6.zip` (دست‌نخورده
