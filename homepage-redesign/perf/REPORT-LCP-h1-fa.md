# علت‌یابی LCP ِ موبایل صفحهٔ نخست تک‌طب — عنصر LCP: `h1#th-hero-title`

**نتیجهٔ کوتاه:** در این دور **هیچ کدی در دو افزونه عوض نشد و نسخهٔ تازه‌ای ساخته نشد.** تنها سازوکاری که عنصر LCP ِ
Production را دقیقاً بازتولید کرد — بارگذاری غیرهمزمانِ `tecteb-home.css` توسط WP Rocket — با یک **تنظیم WP Rocket** برطرف
می‌شود، که طبق دستور شما فقط پیشنهاد می‌شود. بقیهٔ زنجیرهٔ بحرانی Production (IRANMarker، IRANYekan، Font Awesome) مال قالب
یا افزونه‌های دیگر است. بسته‌های قابل نصب همان **Header 0.2.6** و **Homepage 0.3.7** ِ دور قبل‌اند.
**هیچ نصب، تنظیم یا تغییری روی Production یا Staging انجام نشد.**

## ۱. یافته‌ها، با شاهد، اطمینان و ریسک

### ۱-الف. چرا `h1` عنصر LCP است — بازتولید شد (اطمینان: بالا برای سازوکار؛ متوسط برای اینکه همین روی Production رخ می‌دهد)
عنوان Hero با انیمیشن ورود `th-c-rise` (۰٫۷ ثانیه، از `opacity: 0`) ظاهر می‌شود. Chromium اولین رسمِ متنی را که
`opacity: 0` دارد **نادیده می‌گیرد و دوباره نمی‌سنجد**؛ برای همین در هر اجرای محلی با CSS ِ عادی، عنصر LCP لوگوی هدر بود
(`span.tth-logo__word`) نه `h1`. برای اینکه `h1` عنصر LCP شود، باید **اولین رسمش بی آن انیمیشن** باشد.

آزمایش‌ها (هر کدام با یک ویرایش آزمایشی روی همان صفحه، throttle ِ واقعی یا Lighthouse):

| سناریو | عنصر LCP | شاهد |
|---|---|---|
| CSS ِ ما مسدودکنندهٔ رندر، مثل طراحی (وضع فعلی) | **لوگو**، ۵ از ۵ | `perf/evidence/r5-same/` |
| فونت سایت با `font-display: auto` (شبیه IRANYekan)، حتی با ۱٫۵ و ۲٫۵ ثانیه تأخیر فونت | **لوگو** | `mech-E2`، `mech-E5`، `font-P1…P5` |
| **`tecteb-home.css` غیرهمزمان** (کاری که «Load CSS asynchronously» یا «Remove Unused CSS» ِ WP Rocket با یک فایل CSS می‌کند) | **`h1#th-hero-title.th-hero__title.th-in`**، ۵ از ۵ — **دقیقاً همان selector ِ گزارش Production** | `mech-E8`، `mech-E9`، `r5-async-home/` |

پس محتمل‌ترین توضیح برای عنصر LCP ِ Production: **CSS ِ صفحهٔ نخست در لحظهٔ اولین رسمِ `h1` اعمال نشده** — یعنی WP Rocket آن
را غیرهمزمان یا با «Used CSS» بارگذاری می‌کند. این **روی Production تأییدنشده** است و آزمایش تأییدش یک دقیقه طول می‌کشد (بند ۸).

**و این فقط دربارهٔ عدد نیست:** filmstrip ِ Lighthouse در حالت غیرهمزمان (`perf/evidence/lcp-h1/filmstrip-tecteb-home-css-async.png`)
صفحهٔ نخست را در هر ۸ فریم تا ۳ ثانیه **بی‌سبک** نشان می‌دهد (آیکون‌های بزرگ سیاه، فرم خام، بی پس‌زمینهٔ Hero). در حالت
مسدودکننده (`filmstrip-css-blocking.png`) Hero از اولین فریم کامل است. اگر Production از «Load CSS asynchronously» با
critical CSS استفاده کند، بخشی از این پوشانده می‌شود، ولی هر قاعده‌ای که در critical CSS نباشد (از جمله انیمیشن ورود) دیر
اعمال می‌شود.

**و هر دو CSS ِ ما غیرهمزمان = خراب:** با `header.css` هم غیرهمزمان، CLS **۱٫۰۴** و امتیاز ۶۲. CLS ِ Production صفر است، پس
آنجا `header.css` به‌موقع اعمال می‌شود.

### ۱-ب. چرا ۷٫۵ ثانیه — محتمل، اثبات‌نشده (اطمینان: متوسط)
حالتِ غیرهمزمان به‌تنهایی LCP ِ شبیه‌سازی‌شده را محلی **بدتر نکرد** (۳٫۳۱ در برابر ۳٫۶۱ ثانیه)؛ فقط عنصر را عوض کرد. عدد LCP ِ
Lighthouse شبیه‌سازی Lantern است: هر درخواستی را که **پیش از LCP ِ مشاهده‌شده** شروع شده روی شبکهٔ Slow 4G در مسیر می‌گذارد.
روی Production LCP ِ مشاهده‌شده حدود ۱٫۹ ثانیه است (TTFB ۱۲۰ + render delay ۱٬۷۸۰) و پیش از آن، طبق درخت شبکهٔ شما،
`IRANMarker.ttf` (۱٬۱۷۶ms)، `IRANYekanWebLight.woff` (۱٬۱۷۷ms) و Font Awesome Brands (۱٬۲۲۵ms) شروع شده‌اند. پس
**وزن و تعداد درخواست‌هایی که پیش از رسم `h1` شروع می‌شوند** عدد ۷٫۵ را می‌سازند. این تفکیک دقیق بی دسترسی به Production
اثبات‌پذیر نیست.

### ۱-ج. فونت‌ها و آیکون‌ها (اطمینان: بالا برای مالکیت)
| فایل | مالک | شاهد |
|---|---|---|
| `IRANMarker.ttf`، `IRANYekanWebLight.woff` | **نه این دو افزونه** — قالب یا یک افزونهٔ فونت فارسی | جست‌وجو در کل کد هر دو افزونه: صفر ارجاع |
| Font Awesome Brands | Elementor (آیکون فونتی، «Inline Font Icons» خاموش) | روی Elementor ِ واقعی اثبات شد: اگر فقط هدر Elementor ِ جایگزین‌شده آن را لازم دارد، **0.2.6 دیگر بارگذاری‌اش نمی‌کند**؛ اگر فوتر هم شبکهٔ اجتماعی دارد، می‌ماند (`perf/evidence/elementor-real/modes-tests.txt`) |
| Vazirmatn ِ این افزونه‌ها | Header/Homepage | فقط وقتی تنظیم «فونت» روی «همراه افزونه» است؛ در درخت شبکهٔ Production نیامده، که با «فونت سایت» سازگار است (تأییدنشده) |

TTF فشرده نیست (معمولاً ۲ تا ۳ برابر woff2)، و `font-display` ِ این دو فونت را فقط مالکشان تعیین می‌کند.

### ۱-د. CSS ِ مسدودکننده، به تفکیک مالک
در گزارش دور قبل (`perf/REPORT-0.2.6-0.3.7-fa.md` بند ۴) کامل آمده و تغییری نکرده: Header (`header.css`)، Homepage
(`tecteb-home.css`)، Elementor (frontend، Kit، ابزارک‌ها، آیکون‌ها، post-*)، قالب Hello (reset، theme، header-footer)،
WooCommerce (سه فایل)، و افزونه‌های دیگر (`public.css`، `date-picker-custom.css`، فونت‌های فارسی). روی بستر، 0.2.6/0.3.7
CSS ِ `<head>` صفحهٔ نخست را ۳۱ ← ۱۶ کرد.

### ۱-هـ. آیا اصلاح‌های 0.2.6/0.3.7 در Production فعال‌اند؟
**تأییدنشده.** نشانهٔ روشنش در بند ۸ (گام ۱). اگر فعال باشند، `widget-nav-menu`، `widget-search`، `widget-icon-box`،
`e-animation-buzz-out`، `apple-webkit` و `post-<هدر>.css` نباید در فهرست render-blocking ِ PageSpeed بیایند.

### ۱-و. تصویرها، preload، lazy-load، cache
- تصویر Hero: `fetchpriority="high"`، `skip-lazy`، `data-no-lazy="1"`، ابعاد صریح؛ WebP. لوگوی هدر: WebP، `fetchpriority="high"`.
- preload: فقط Vazirmatn و فقط وقتی فونت افزونه انتخاب شده؛ آزمایش شد که برداشتنش FCP را بدتر می‌کند (۲٫۰۰ ← ۲٫۵۶ ث).
- cache headers ِ Production: **تأییدنشده**.

### ۱-ز. Forced reflow و JS ِ بی‌استفاده
- `tecteb-home.js` اندازه‌گیری را فقط داخل `pointermove` انجام می‌دهد (نه هنگام بارگذاری).
- `header.js` یک بار `offsetHeight` ِ نوار را هنگام راه‌اندازی می‌خواند؛ در ۱۰ اجرای محلی Lighthouse هیچ reflow ای به آن
  نسبت داده نشد. تغییرش ریسک برگشت CLS ِ هدر را داشت و شاهدی برای سود نبود — **دست نخورد**.
- JS ِ بی‌استفاده (~۱۹۰KiB در گزارش شما) از jQuery، Elementor و WooCommerce است؛ JS ِ این دو افزونه با هم ۱۲ کیلوبایت است.

### ۴-ب. اگر ترجیح می‌دهید افزونه خودش ردیف ۱ را انجام دهد (نیازمند تأیید؛ ساخته نشده)
یک فیلتر کوچک در Homepage (و Header) که فقط وقتی WP Rocket «Load CSS asynchronously» را روشن دارد اثر دارد:
`add_filter( 'rocket_exclude_async_css', fn( $u ) => array_merge( (array) $u, [ <نشانی tecteb-home.css>, <نشانی header.css> ] ) );`
بی WP Rocket هیچ اثری ندارد و ظاهر را عوض نمی‌کند؛ ولی چون رفتار WP Rocket را عوض می‌کند، طبق دستور شما فقط با تأیید
ساخته می‌شود.
